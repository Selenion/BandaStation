# Компактные показания и прямой обмен вентиляции с Rust

Проект от 2026-11-05 для `rust-atmos-pipes`, исходный коммит `995fbfb91e9`.
Реализация после подключения прямого C API для труб описана в
[отчёте о переносе](VENT_TRANSFER.md). Rust выполняет изъятие и слияние,
читая и обновляя живой порт через C API.

Проект расширен: [хранение смесей сетей и портов, смешивание и реакции в Rust](PIPE_NATIVE_DESIGN.md).
Этот документ описывает первый подпроект и его промежуточную границу с DM;
целевая граница и последующие этапы определены в расширенном проекте.

Цель первого этапа — перестать получать полный DM-объект воздуха тайла ради
проверки давления/температуры и обычного переноса газа вентиляцией. Формулы,
порядок устройств и наблюдаемые эффекты Banda сохраняются. При новой
подтверждённой несовместимости способ исправления согласуется с пользователем.

## Граница первого этапа

- Rust хранит воздух тайла, вычисляет компактные показания и выполняет
  добавление/изъятие газа непосредственно над ним.
- DM сохраняет объект вентиляции, проверки питания/узлов/сварки, повреждение
  от разгона, настройки, выбор количества переноса и `update_parents()`.
- `airs[1]` остаётся самостоятельной DM-смесью. Её `remove()`/`merge()`
  сохраняют сигналы, порядок ключей, тип образца и удерживаемые ссылки.
- Через границу передаётся образец переносимого газа, а не весь воздух тайла
  с архивом и результатами реакций. Промежуточный образец порта пока остаётся.
- Используются существующие DLL, хранилище мира и безопасные фазы. Короткие
  операции API выполняются синхронно перед worker. Перенос численной фазы
  оборудования в worker — следующий этап после переноса его буферов.
- Скрубберы, насосы между сетями, химия труб и перестроение сетей в этот этап
  не входят. Новый процесс, affinity, постоянное DM-зеркало карты не добавляются.

Обоснование: перенос всего `vent_pump.process_atmos()` сейчас потребовал бы
синхронизировать ещё и порт устройства, его сигналы и побочные эффекты.
Удаление полного представления воздуха тайла проверяет основную гипотезу
меньшим изменением. Этот этап сам по себе не переносит CPU вентиляции в worker.

## Компактные показания

Предлагаемый минимальный результат: давление, температура, объём, теплоёмкость.
Для чтения температуры/давления не создаются `cached_air`, `readonly_air`,
`committed_air`, архивные списки и списки результатов реакций.
Маска газов пока не нужна: её потребитель, скруббер, остаётся на прежнем пути.

Пакет запрашивает не более 256 ID в порядке переданного списка, аналогично
существующим ограниченным пакетам `byond_world.rs`. Ответ имеет версию формата,
эпоху опубликованного кадра, число записей и для каждой записи:
`status, binding_version, pressure, temperature, volume, heat_capacity`.
Отсутствующий воздух — отдельный статус, не нулевое давление. ID и версии
проверяются по существующим ограничениям точного представления целых в BYOND.
Номер операции выбирается при реализации; возможность проверяется при запуске
адаптера, а не на каждом вызове устройства.

Правила чтения:

1. Используется опубликованный кадр; получение показаний не запускает реакций,
   не будит тайл, не меняет архив и не заставляет завершать worker ради чтения.
2. В безопасной фазе уже изменённая DM-смесь имеет приоритет над снимком Rust,
   как в текущем `read_air()`. Если существует полный DM-кэш, первоначальная
   реализация использует действующий путь чтения: удерживаемая ссылка могла
   быть изменена напрямую, без вызова мутирующего proc.
3. Пакетные значения действуют только для неизменённой привязки и воздуха.
   Эпохи недостаточно: два устройства могут изменить один тайл внутри кадра.
   Каждая прямая операция обновляет/инвалидирует его показания. Создание полного
   кэша переводит следующие чтения на правило 2. Новый кадр, начало rebind,
   закрытие адаптера и ошибка получения пакета сбрасывают краткий кэш.
4. При `pending_rebind`, незавершённом Initialize, отсутствии регистрации,
   нестандартной смеси или неподдержанном состоянии используется штатный путь.
   Лава и прочие переопределения `GetTemperature()`/`GetHeatCapacity()` сохраняются.
5. Давление вычисляется по `return_pressure()` Banda, включая нулевой объём.
   Теплоёмкость учитывает тип смеси и космос. Порогов Paradise не добавляем.

Первый вариант предвыборки — ограниченный участок уже существующего
`SSair.currentrun` перед его обработкой, с устранением повторяющихся ID.
Сбор ID не исполняет игровые проверки и не меняет порядок вызовов машин.
После паузы MC пакет строится заново. Отдельный постоянный реестр наблюдателей,
обход карты и массив размером 780300 записей не нужны.
Стоимость дополнительного просмотра оборудования включается в замер.
Геттер вне этой предвыборки сохраняет штатное чтение; FFI-вызов для каждого
одиночного числа не является предлагаемой оптимизацией.

## Прямой перенос газа

Общие операции размещаются рядом с существующим API доступа к воздуху.
Вентиляция использует их как конкретный потребитель; нельзя молча изменить
контракт `assume_air()`/`remove_air()` для всех типов объектов.

### Подача

1. DM выполняет прежние проверки, получает компактные показания и рассчитывает
   количество по исходной формуле. Износ вентилятора остаётся до этой проверки.
2. `airs[1].remove(amount)` выполняется в DM, как раньше. Нулевой результат
   не вызывает добавление воздуха или уведомление сети.
3. Rust принимает только образец. Для добавления переиспользуется арифметика
   `cell::merge` и механизм `Write::Release`, после проверки состояния владельца
   и актуальной привязки. Операция завершается до следующего устройства.
4. Сохраняются обновление газовых оверлеев, активация тайла и затем
   `update_parents()`. Обновление изображения не должно неявно получить полную
   смесь: используется компактное представление видимых газов и существующая
   логика сравнения оверлеев, включая исчезновение последнего видимого газа.

После `remove()` получатель определяется заново через текущий `loc`, как
в исходном proc: сигнал смеси мог изменить состояние. Если быстрый путь
стал недоступен, тот же уже извлечённый образец передаётся штатному
`assume_air()`. Повторять `remove()` или весь `process_atmos()` нельзя.

### Отсос

1. Проверки давления, температуры, лимита 50 атмосфер и целостности остаются DM.
2. Rust удаляет количество из текущего воздуха и возвращает только образец.
   Это новый синхронный контракт: при занятом worker возвращать выдуманный
   образец или ставить изъятие в очередь запрещено. Сначала действующая
   `enter_safe_phase()`, затем повторная проверка привязки.
3. Удаление повторяет `gas_mixture.remove()`: ограничение доступными молями,
   порядок газов, QUANTIZE и очистку текущих **и архивных** ключей. Нельзя просто
   переиспользовать hotspot `remove_ratio()`, который не обслуживает архив тайла.
4. DM выполняет `airs[1].merge(sample)` и `update_parents()` в исходном порядке.
   Тип образца и его теплоёмкость сохраняются: пустой turf-образец и обычная
   пустая смесь не взаимозаменяемы при температурном балансе.

Если вызванный `remove_air()` вернул пустой образец/null, его собственные
обновление оверлеев и активация всё равно повторяются, как в базовом turf proc;
вентиляция затем пропускает merge и уведомление сети. Отдельное переопределение
космоса этих действий не выполняет.

Первоначальная граница быстрого пути — обычный поддержанный открытый тайл,
актуальная привязка, отсутствие выданного полного DM-кэша/изменяемых заимствований
и переопределений операции. Для остальных случаев вызывается существующий DM-путь
до совершения переноса. В частности, `/turf/open/space/remove_air()` возвращает
`null`, а не результат `immutable/space.remove()`; космос остаётся на штатном пути.

Так сохраняются удерживаемые смеси и их списки без массового обновления зеркал.
Частота fallback измеряется: если быстрый путь почти никогда не используется,
это основание пересмотреть проект, а не объявлять перенос успешным.

Прямой быстрый путь первоначально включается только в штатной общей фазе машин,
которая сохраняет выполненные записи при ошибке (`commit_on_error=TRUE`). Вне
этого контекста остаётся прежний путь: одного `in_safe_callback` недостаточно,
чтобы менять правила отмены вложенного callback. Признак области действия
сбрасывается и при исключении. Стенд обязан проверить именно эту фазу и
подтвердить ненулевое число прямых операций, иначе он может проверить лишь fallback.

Пакет проверяется целиком до изменения native-состояния. Выделение и выдача
ответа для изъятия выполняются до его фиксации; ошибка не должна терять газ.
После подтверждённой операции её нельзя повторять через fallback. Ошибка
последующей машины сохраняет уже выполненные переносы, согласно действующему
`commit_on_error=TRUE`. Ошибки публикации не должны оставлять доступными старые
компактные показания. Между операцией и её DM-последствиями нет нового yield.

Подача/изъятие сами не запускают химию немедленно: текущие world-owned
`assume_air()`/`remove_air()` этого не делают. Фаза реакций остаётся прежней.

## Проверки до подключения

Четыре существующих сценария `vent_pump_checks()` проверяют `idle`, `release`,
`siphon`, `empty_pipe`; они не покрывают новый контракт. Расширять следует этот
стенд, а не заменять его эталон новыми Rust-результатами.

| Группа | Обязательное наблюдение |
| --- | --- |
| Компактные чтения | Совпадение с DM P/T/V/C для 20 газов, vacuum, обычной и turf-смеси; чтение не меняет архив, активность, COW-страницы и полный DM-кэш |
| Актуальность | Две вентиляции на тайле; подача перед отсосом и наоборот; DM-запись перед чтением; несколько обращений в одной безопасной фазе |
| Привязка | ChangeTurf с наследованием и без, pending_rebind, поздний Initialize, перемещение вентиляции, закрытие адаптера |
| Режимы вентиляции | Все комбинации pressure_checks, обе стороны переноса, high_volume, выключенное питание/узел/on, welded, разгон и повреждение |
| Пределы | Нулевой/малый образец, истощение порта, точная граница 50 atm, давление ниже/на/выше уставки, минимум температуры, молярное округление |
| Состояние смеси | Моли/температура обеих сторон, порядок ключей, архив, reaction_results, last_share, тождество удерживаемых объектов и списков |
| Побочные эффекты | Число и порядок сигналов, update_parents, активация тайла и оверлеи при появлении/исчезновении газа |
| Ошибки | Ошибочный/обрезанный пакет до записи, устаревшая версия, ошибка выдачи ответа, ошибка следующей машины, отсутствие повторного переноса |
| Worker | Прежний порядок фаз, число завершённых расчётов и MC-вызовов, чтение во время работы, синхронизация перед изменением |
| Длительная цепочка | 10000 последовательных подач/отсосов с эталоном DM и проверкой сохранения газа/энергии с учётом исходного округления |

Флаги, порядок, побочные эффекты и тождество ссылок проверяются точно.
Для чисел применяется существующий допуск стенда (`transport.difference`:
`rel_tol=2e-5`, `abs_tol=2e-5`); он не разрешает менять решение на пороге,
терять газ или накапливать систематический дрейф. Прежнее разрешение пользователя
на несущественное округление не является разрешением менять игровую механику.

## Замеры и критерии принятия

Три сборки: исходный DM, текущий Rust от `995fbfb91e9`, кандидат с теми же
AVX2/worker. На каждом завершённом шаге изолируется его вклад: сначала только
показания, затем показания плюс прямой обмен. Смешивать эффект с переносом
трубных сетей или изменением настроек worker нельзя.

Сначала фиксированный стенд: много вентиляций в равновесии, непрерывная подача,
отсос, смешанная последовательность и теплообменные трубы. Затем покой, пожар
и взрыв СМ на полной MetaStation. Минимум три чередующихся парных прогона,
одинаковые DLL features, seed, карта и фактическое число устройств/сетей;
при разбросе, перекрывающем разницу, вывод об ускорении не делается.

Сохраняются CPU-s процесса/main/worker, CPU-ms на завершённый расчёт, расчёты
за реальную секунду, private/RSS и пиковый commit, время инициализации.
Отдельно: количество полных чтений воздуха, чисел через FFI, вызовов DLL,
быстрых операций и fallback по причинам. Эти диагностические счётчики не
должны незаметно утяжелять только одну сравниваемую сборку.

Экономия ресурсов подтверждается сокращением суммарного CPU/памяти при том же
объёме выполненных расчётов и сохранении поведения. Снижение CPU главного потока
без общего выигрыша отдельно называется его разгрузкой. Одно уменьшение
количества вызовов не доказывает экономию. Для реакции сервера
добавляется замер от изменения уставки до наблюдаемого изменения воздуха;
CPU-ms не называется задержкой. При неизменной фазе не обещается ускорение тиков.
Известные исходные runtime обрабатываются действующим классификатором; новые
атмосферные ошибки, потеря расчётов и незавершённый сценарий не игнорируются.

## Файлы и порядок работ

1. Расширить `tools/atmos/api_world.dm.in` и проверки `phase_world.py`, получить
   исходный DM-контракт. Зафиксировать исходные хеши, число проверок и результаты.
2. Реализовать ограниченный пакет показаний в `rust/atmos/src/byond_world.rs`
   с проверками Store/FFI; чтение в `modular_bandastation/atmos_rust/code/access.dm`.
   Подключить предвыборку в `air.dm`, потребителей в `vent_pump.dm` и
   `_open.dm`; проверить все вызовы и переопределения обоих температурных геттеров.
3. Измерить этот шаг отдельно. Затем добавить прямые операции в существующий
   Store/API, покрыть публикацию/ошибки и подключить только вентиляцию.
4. Снова выполнить функциональные и полные нагрузочные сравнения. Отдельный
   отчёт показывает экономию и ограничения, включая долю fallback.

Изменения upstream-файлов отмечаются BANDASTATION. Если новый `.dm` действительно
понадобится, он добавляется в `_atmos_rust.dme`. Config, UI, карты и переводы
первому этапу не нужны. Коммит, push и PR не входят в это проектирование.

## Сопоставление с Paradise

Сохранённая версия `5aca8afbcf00ef1f2bb96e179bf1389289551689`:
[архитектура](PARADISE_ARCHITECTURE.md). `milla_get_watched_tiles()` возвращает
давление и маску газов; приборы могут завершиться до получения полной смеси.
Подача использует `blind_release_air`, отсос — `milla_safe`.
Трубопроводы и оборудование остаются DM. Заимствуем компактное чтение и безопасную
границу, сохраняя собственные формулы, типы смесей и последовательную актуальность
Banda. Перенос порогов/предыдущего снимка Paradise как нового игрового правила
не входит в проект.
