# Переход потребителей смесей на Rust API

Ветка: `rust-atmos-api`, создана от `rust-atmos-pipes` без коммита.
Исходные незакоммиченные изменения сохранены в `tmp/atmos-api-start-01/`.

Цель: убрать постоянные DM-копии воздуха и их повторную сверку. Полное
сохранение поведения Banda: формулы, порядок, архив, нулевые ключи газов,
сигналы, исключения, сохранённые ссылки, замена пола и закрытие адаптера.
При подтверждённом расхождении решение согласуется с пользователем.

## Этапы

- [x] Создать ветку и сохранить начало работы без коммита/пуша.
- [ ] Инвентаризировать потребителей: чтение, изменение, сохранённые ссылки,
  сигналы, UI, приборы, дыхание, ёмкости, сети, порты, реакции и пробы газа.
  Автоматический список кандидатов не означает завершённого ручного аудита.
- [x] Дать общему API пакетное чтение чисел и состава из Rust без создания
  `/datum/gas_mixture`. Использовать существующий учёт версий и готовый кадр,
  учитывать ещё не опубликованные операции текущей безопасной фазы.
- [x] Перевести общие `GetTemperature`/`GetHeatCapacity` и проверки огня;
  проверить новый и прежний путь с реальными потребителями и ошибками.
- [ ] Перевести остальные читатели, затем передачу воздуха через сигналы.
  Учитывать порядок чтений относительно вызовов, которые сами меняют воздух.
- [ ] Перевести изменения на существующий протокол операций. Не подменять
  прямую запись методом с другими ограничениями/округлением/сигналами.
- [ ] Перевести сохраняемые ссылки и отдельные пробы на Rust-хранение.
  Старая ссылка после замены пола должна сохранять исходную семантику,
  но не должна случайно менять воздух нового пола. Проверить время жизни.
- [ ] Закрыть оставшихся потребителей сетей/портов/ёмкостей и производные
  классы смесей. Удалить fallback только после перевода всех его вызывающих мест.
- [ ] Удалить больше не нужные постоянные кэши/публикацию/проверки копий.
- [ ] Сравнить на одинаковых входах, объектах, командах и числе расчётов:
  CPU процесса/main/worker, стадии, количество полных DM-смесей и память.

## Ограничения реализации

Один запрос возвращает сразу нужные данные; не добавлять DLL-вызов на каждый
газ или каждое поле. Ответ со значениями — временные данные, а не вторая
авторитетная смесь. Для ещё не переведённых держателей живой DM-смеси
совместимый путь временно остаётся; он не должен создавать кэш новым читателям.

Нельзя считать одно чтение гарантией отсутствия последующих прямых записей.
Архивные моли, результаты реакций, порядок ключей и присутствующий ноль —
часть контракта, как и температура. Полный список состава должен сохранять
эти различия там, где вызывающий код их использует.

Контроль до изменений: `tmp/atmos-fixed-cost-03/`,
[измеренные затраты](../profiling/ATMOS_COST_REPORT.md). Его принудительные
DM-ссылки нужны для проверки совместимости; измерение их устранения требует
равнозначного потребителя через API, а не простого выключения этих обращений.

## Выполненная часть

`native(87)` принимает до 256 адресов ячеек/портов за вызов. Чтение заимствует
готовое состояние Rust без клонирования смеси; видит операции текущей безопасной
фазы. Полный состав сохраняет порядок ключей и присутствующие нули. Выборка
отдельных газов возвращает количества в порядке запроса; отсутствие в ней равно
нулю, поэтому проверку наличия ключа нельзя заменять проверкой количества.

`return_air_values()` возвращает временные численные показания. При отсутствии
Rust или при выданной живой DM-смеси сохраняется прежний источник. Старые DLL
определяются пробой возможности; конфигурация и ABI 11 сохранены. Временные
DM-списки всё ещё выделяются: устранена постоянная смесь и её синхронизация,
а не все выделения памяти на границе языков.

Переведены: общие температура/теплоёмкость, `TakeTemperature`, предварительные
проверки зажигания, давление для речи/слуха, проверка кислорода для мышей и
костра, испарение мокрого пола, оттаивание предметов при перемещении,
перепад давления около стен, карманная ветряная турбина, безопасность прибытия,
показания температуры компьютера турбины, допуск сверхпроводимости и
проверки давления/количества газа у газодобывающей машины.

`TakeTemperature` использует существующий протокол операций и сохраняет прямое
прибавление температуры без нового ограничения снизу. Изменение доступно
следующему чтению той же фазы до окончательной записи. Живые ссылки остаются
приоритетными до миграции их владельцев; проверки копий не отключены.

Проверка `tmp/atmos-phase/api-values-03/`: 12 сценариев мира, 49 графов/980 шагов,
99 проверок API, 31 проверка worker, прежние проверки эффектов/ошибок/замены
пола; 0 расхождений и 0 runtime. Новые 16 проверок включают чтение при работающем
worker без ожидания и создания привязки. Полный набор Rust-тестов прошёл.

Сравнение с локальным Paradise (`5aca8afbcf00ef1f2bb96e179bf1389289551689`):
его `bound_to_turf/set_dirty()` обновляет выданную read-only смесь сразу.
Поэтому утверждение «Paradise вообще не держит DM-копии» неверно. Здесь
чистые читатели постепенно обходят смесь; оставшиеся владельцы прямых
ссылок сохраняют прежний контракт Banda. Auxmos также держит газ в Rust
(`src/gas.rs`, `GasArena`), но доступ идёт через ID и блокировки; копирование
этого устройства без перевода вызывающих мест проблему прямых DM-полей не решит.

## Что ещё не закончено

Первичная текстовая выборка содержит 969 строк в 214 игровых файлах и 556 procs,
плюс реализацию смесей/адаптера/тесты. Это кандидаты, не завершённый ручной
аудит. Расширение поиском вызовов методов (в том числе через поля с другими
именами) дало 1675 строк в 271 игровом файле / 684 procs. Совпадение имени
метода не доказывает тип смеси. Итоговый состав воспроизводится `operation_audit.py`;
динамические ссылки требуют проверки по вызывающим местам.

Основные оставшиеся семьи: окружение/дыхание мобов и органы, анализаторы/UI,
сигналы воздействия, топливо/реагенты, переносные ёмкости, механизмы газовых
реакторов, сохраняемые образцы, нестандартные смеси и возврат в DM при закрытии.
Рабочий путь вентиляции/скрубберов и сетей уже использует существующие Rust ID,
но выдача смеси и сигналы оставляют совместимый путь. Постоянные кэши нельзя
удалять, пока остаются их потребители. Этап полного отказа от них не завершён.

Новый замер: `air_access_bench.py`, одинаковые чтения температуры/теплоёмкости
до и после каждого кадра, один бинарник/DLL, режим API включается на экземпляре
адаптера. Исходные данные и квота порций неизменны. Это ограниченный стенд
общих читателей, а не сравнение всего раунда с исходным DM.
Серия завершена: 16 случаев / 640 расчётов с одинаковым состоянием и работой;
[результат первого этапа](AIR_ACCESS_REPORT.md).

## Живой доступ: решение пользователя выполнено

Кандидаты дыхания и температуры кожи прошли обычное сравнение с отдельными
исходными DM-procs (105 проверок API, `api-actors-01`). Дополнительный тест
с настоящим баллоном и тестовым газообразующим обработчиком удаления HUD
показал: ранний снимок количества газа даёт вдох 0,199 вместо 0,398 моля.
Газ не теряется; живое чтение после callback заменено преждевременным чтением.
Пользователь выбрал живую ссылку на смесь в Rust. Она реализована и подключена
к дыханию. `live-reference-05` прошёл 126 проверок API и прежние игровые
сценарии без расхождений и runtime. Подтверждены чтение после газообразующего
callback, сохранение прежней смеси при замене пола, изменения в `Destroy`,
ошибки и закрытие адаптера. [Устройство и проверки](LIVE_REFERENCES.md).
Замер одинаковых циклов вдоха/возврата газа завершён: 16 случаев / 640 расчётов,
50 тестовых персонажей, одинаковые состояния и работа. CPU на расчёт снижен
на 5,1% на пожаре и 5,9% на плазме через трубы; полных постоянных кэшей 0 вместо
50. Это добавочный выигрыш дыхания внутри Rust-атмоса, не сравнение с чистым DM
и не полный `Life`. Причинного выигрыша памяти последовательный прогон
с остановленным GC не доказывает. [Числа и ограничения](LIVE_REFERENCES.md).
Дальше: `Life/handle_environment` и следующие владельцы смесей, отдельные
процессы для замера памяти. Весь проект миграции не считается завершённым
по результатам этих этапов.

## Life/handle_environment — текущий этап

Начало сохранено без коммита в `tmp/atmos-life-start-01/`.
Переведены вызов из `Life`, восемь переопределений мобов, обработчики давления
и газов вида, естественная терморегуляция. Используется существующая живая
ссылка; прежние аргументы и места чтения сохранены. Для различения отсутствия
газа и присутствующего нуля добавлено чтение полного уже существующего пакета.
Rust/DLL не менялись. Контрольная цепочка исходных DM-procs сохранена отдельно
в `original_life_consumers.dm.in`.

`life-api-02` скомпилировался без ошибок и проверил 192 условия API, но не принят.
Подтверждено расхождение: обработчик давления получает DM-смесь вне безопасного
callback и напрямую прибавляет 17 молей; последующий обработчик состава видит
117 в DM и 100 через новую ссылку. Итоговый газ сохранён (117). `read_air()`
выдал `readonly_air`, а `references.values()` переключился на `cached_air`.
Это ошибка свежести чтения, а не изъятия/баланса. Обработчик с прямой записью
был искусственным тестом старого интерфейса, а не найденным игровым потребителем.
Пользователь уточнил цель: откатить последнее переключение на фактически
выданную DM-смесь и переводить реальные обращения на Rust API/операции.
Последнее переключение (`air_reference_issued` и его вызовы) удалено.
Тест теперь сравнивает `adjust_gas` исходного DM с той же Rust-операцией,
не закрепляя произвольную запись в DM-копию как обязательный новый интерфейс.

Дополнительно найдены и переведены реальные потребители из `Life`:
`slime.handle_slime_stasis` читает BZ и общее количество одним пакетом;
`tree.Life` читает CO2, затем изымает его через AdjustGas и добавляет O2
штатным `atmos_spawn_air` (Merge/Archive). Сохраняются проверка запаса,
QUANTIZE, теплоёмкость добавки, архивирование и активация.
Общий `atmos_requirements`, вызываемый дыханием животных, тоже создавал кэш.
Его показания читаются до Collect, а очистка текущих и архивных молей
выполняется операцией Rust. Временные нулевые ключи assert/GC не передаются
в DM: после исходного GC они всё равно удалены; отдельный тест проверяет
чтение малого количества до очистки и оба набора ключей после неё.
Неизменяемый воздух космоса не меняется и не требует кэша/мутабельной привязки.

Два дефекта самого нового теста исправлены отдельно: нельзя создавать
абстрактного `/mob/living/carbon` (ошибки инициализации/удаления); заменён
на настоящую личинку. `set_gas(gas, 0)` штатно удаляет нулевой ключ через
`garbage_collect()`, поэтому присутствующий ноль задаётся прямой записью.
Эти ошибки не исправляются в игровой логике и не добавлены в список допустимых runtime.

Готовится `life_access_bench.py`: один бинарник, меняется только путь Life,
дыхание использует новый API в обоих вариантах. Каждый случай в отдельном
DreamDaemon, работающие MC/GC и `SStime_track`, одинаковые 4096 тайлов,
50 персонажей и 40 расчётов. Проверка газа/портов/эффектов/состояния тел и числа
выполненных `Life/handle_environment` предшествует сравнению ресурсов.
`life-api-05`: 198 условий API без расхождений, 0 runtime, но процесс аварийно
завершился после `BANDA_ATMOS_PHASE_INTEGRATION_COMPLETE`. Windows Event 1000
указал `rust_g.dll_unloaded`, `0xc0000005`; такой запуск не принят. Внешнюю
библиотеку в рамках этой задачи не меняем. Повторная расширенная проверка:
`life-api-07`, 204 условия API, включая очистку и космос.
Снимок измерений: `tmp/atmos-life-bench-02`, обновлён до первого capture;
история обновлений и контрольные суммы сохранены в provenance.
Результатов CPU/ТД/памяти этого этапа пока нет; сравнение запускается после
принятой игровой проверки и короткого контрольного прогона стенда.

Пользователь согласовал отдельное отличие для пустого космоса: сохранять TCMB
(2,7 K), не воспроизводить временное охлаждение общего DM `space_gas`.
`try_scale_air_temperature` пропускает запись только для native air kind 3;
обычные и планетарные смеси используют исходное умножение. У ауры пустотного
еретика сохранены остальные ветви: холод тела и статусы, повреждение объектов,
запуск бури. Тест вызывает настоящую ауру и отдельно замороженный исходный proc;
охлаждение помещения, тело/статусы и повреждение двери, решётки, окна должны
совпасть. Температура соседнего и удалённого пустого космоса проверяется по
согласованному исключению; постоянные DM-кэши не должны появляться.

В аудит Life дополнительно включены pressure/body-temperature elements,
void adaption, emulsijack и плазменная фиксация. Для них есть отдельные
сравнения с исходными DM-procs. Создание временной смеси добавляемого газа
не является кэшем Rust-воздуха и в этом этапе не меняется. Собственные смеси
баллонов/герметичных контейнеров и проксирование через обычные контейнеры
остаются следующей семьёй потребителей; полный отказ проекта от DM-смесей
этим этапом не заявляется.

Новый снимок стенда: `tmp/atmos-life-bench-05`, собран без ошибок/предупреждений.
В отличие от прежнего smoke, построение геометрии и smoothing завершаются
до измерительного окна. В обоих режимах работает MC/GC; посторонние
срабатывания подсистем отклоняют замер. Режимы отличаются только чтениями
окружения из Life; дыхание использует Rust references в обоих вариантах.
Это сравнение этапа Life внутри Rust-атмоса, не нового Rust с чистым DM.

`life-api-11` принят: 245 проверок API, 12 сценариев мира, 49 графов/980 шагов
и прежние проверки очередей/механизмов, 0 расхождений, 0 runtime, завершение 0.
SHA отчёта: `04e1fbe8283566a1f54e04c863209559a06a44753399f266500e47a2846c578d`.
В настоящей ауре совпали 263,835 K воздуха помещения, 265 K тела,
холод/немота/размытие и прочность объектов 127/20/20. В обоих проверяемых
тайлах космоса Rust сохранил 2,7 K; исходный DM временно даёт 2,43 K.
Тест бури использует уже существующий datum, не запускает погоду всей станции.
Первый расширенный прогон (`life-api-10`) отклонён: тест передал 442 тайла
одним пакетом при штатном лимите 256. Исправлена только подготовка теста.

Этап завершён проверкой и замерами: `atmos-life-bench-05/report.json` принят,
16 отдельных DreamDaemon / 640 расчётов, включая 12 основных запусков без
профайлера и 4 профиля. Состояния и работа одинаковы, runtime нет.
CPU/расчёт: пожар −3,9%, плазма −7,5%; CPU главного потока −3,9% и −7,7%.
Постоянных кэшей на этих путях 50 → 0. На пожаре улучшения скорости/ТД нет;
на плазме в серии ТД ниже. Экономия памяти не доказана. Профиль связывает
экономию с удалением сравнений списков и обновления копий; основная публикация
с игровыми эффектами на пожаре почти не ускорилась.
[Отчёт Life](LIFE_ACCESS_REPORT.md), [результаты](LIFE_ACCESS_RESULTS.json).
Следующие владельцы — контейнеры и прочие ещё не переведённые потребители.
