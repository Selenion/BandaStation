# Живые ссылки на воздух в Rust

Выбранный пользователем способ устранения расхождения дыхания реализован
в ветке `rust-atmos-api`. Ссылка захватывает идентичность смеси, а значения
читает в момент использования. Она не является ранним численным снимком.

## Устройство и время жизни

`return_air_reference()` возвращает `/datum/banda_atmos_air_reference`.
Обычная Rust-смесь не декодируется в DM. Чтение `total_moles()` или `values()`
видит опубликованное состояние и изменения текущей безопасной фазы.
В `carbon/breathe` количество читается на прежнем месте — после выбора
баллона, непосредственно перед изъятием образца. Сам образец и лёгкие сохраняют
существующий путь. Чистый DM и прежние DLL используют прежнюю живую смесь.

Вызывающий код владеет ссылкой и вызывает `qdel()` как при успехе, так и
при исключении. Она освобождается до проверки/возврата образца дыхания.
Это не владелец исходной DM-смеси: удалять её при освобождении ссылки нельзя.

Слоты и поколения ID используют существующий пул сетей, обобщённый для двух
реальных типов записей. Пул ссылок отделён от пула газовых смесей труб.
В обычной записи находятся адрес исходной смеси и пустое поле сохранённого
состояния. Регистрация ссылки не копирует смесь или карту.

При смене привязки, прямой замене смеси или удалении источника Rust сохраняет
один `Sample` для ещё живых читателей. Несколько читателей разделяют его через
`Arc`; последняя освобождённая ссылка освобождает и образец. Новые ссылки
получают новую смесь, старые не начинают читать воздух новой поверхности.
Обычные изменения газа не запускают обход списка ссылок.

## Совместимость во время миграции

Если код уже держит DM-смесь либо запрашивает её во время действия ссылки,
чтение сохраняет приоритет её прямых полей. Ссылка удерживает тот же объект;
новое полное зеркало карты не создаётся. Обработчики удаления пола могут
материализовать прежний воздух штатным путём. Такие старые объекты отсоединены
от новой версии привязки, но остаются доступны завершившимся позже читателям.

Временная смесь старого пола освобождается из привязки при завершении удаления.
Сама ссылка при необходимости держит её до конца своего обращения.
При закрытии адаптера текущие ссылки переключаются на восстановленный воздух
DM, а сохранённые прежние смеси декодируются отдельно. Затем связи с владельцем
и нативные ID освобождаются. Существующая конфигурация не меняется.

Пока поддержаны чтения чисел и выбранных газов. Нулевое количество выбранного
газа не различает отсутствие ключа и присутствующий ноль. Потребителей,
проверяющих именно наличие ключа, нельзя переводить такой заменой.
Изменения газов продолжают использовать существующий протокол операций.

## Дополнение ABI 11

Все номера аддитивны; `native(88)` проверяет возможность. Адрес источника
сохраняет существующий вид `[kind, id, version]`; адрес ссылки — `[slot, generation]`.

| Операция | Аргументы после владельца | Результат |
| --- | --- | --- |
| 88 | без аргументов | Возможность живых ссылок |
| 88 | `0, source, output` | Регистрация; `output = [slot, generation]` |
| 88 | `1, handle` | Освобождение с проверкой поколения |
| 88 | `2, output` | Число живых ссылок в `output[1]` |
| 89 | `handles, gas_ids, all_gases, output` | Пакет чтений в формате 87; статус 1 — живая смесь, 2 — удерживаемая прежняя, 0 — недействительная ссылка |
| 90 | `handle, air_output, archive_output` | Полный образец для перехода обратно в DM; результат — исходный класс смеси |

Нулевой счётчик возвращается внутри пакета: ноль как прямой результат
`call_ext` трактуется существующим DM-адаптером как ошибка операции.

## Проверки

Полный Rust-набор прошёл на `i686-pc-windows-msvc` с `byond,simd,worker-profile`:
136 тестов, из них 52 внутри библиотеки. Три новые проверки ссылок: свежесть
незавершённых изменений, поколения и повторное освобождение, смена смеси/пола,
удаление, публикация worker, порты, закрытие и ограниченный рост таблицы.
Проверка `Weak` подтверждает освобождение сохранённого образца последним читателем.

`tmp/atmos-phase/live-reference-05/`: 126 проверок API, 12 мировых сценариев,
49 графов/980 шагов, прежние проверки worker/ошибок/групп/огня — 0 расхождений,
0 runtime. Вдох при изменении газа обработчиком баллона: **0,398 / 0,398 моля**
в исходном DM и Rust. При смене пола во время того же вызова сохранён исходный
вдох из прежней смеси. Правки `Destroy()` видны старой ссылке; новый пол получает
свой воздух. Ошибка оборудования не оставляет живых нативных ссылок.

В callback замена пола может временно оставлять новый воздух в DM до штатной
очереди перепривязки. Тест сравнивает публичный API во время этой границы и
сырой Rust-снимок после завершения очереди, без дополнительного расчёта газа.

В Paradise `bound_to_turf/set_dirty()` немедленно обновляет выданную копию.
Здесь для переведённых читателей эту роль выполняет чтение по живому ID;
остальные DM-алиасы пока сохраняются. Полная миграция `Life/handle_environment`,
сигналов, приборов и сохраняемых образцов ещё не завершена.

## Замер одинаковой работы

`tmp/atmos-live-bench-01/report.json`: 4096 тайлов, 50 тестовых персонажей,
40 расчётов на случай, три обычных повтора и один отдельный с профайлером.
16 случаев / 640 расчётов / 32000 циклов дыхания; состояния газа, порты,
последовательность эффектов, показания и число заданий worker совпали.
Нативных ссылок после обращения не осталось, runtime нет. Основные окна
проверены на выключенный профайлер. Один бинарник/DLL; меняется только
доступность живых ссылок, скалярный API включён в обоих вариантах.

Здесь `legacy` означает прежний совместимый путь дыхания с живой DM-смесью
внутри Rust-атмоса. Это **не сравнение с чистым DM**. `check_breath()` тестового
персонажа только считает образцы и возвращает их без метаболизма: замеряет
границу чтения/изъятия/возврата газа, а не полный `Life` или нагрузку 50 игроков.
MC и GC остановлены, квота эффектов одинакова (128). ТД этим стендом не измерен.

Время — миллисекунды на выполненный расчёт, медиана трёх обычных повторов:

| Показатель | Пожар: legacy → API | Плазма через трубы: legacy → API |
| --- | --- | --- |
| CPU всего процесса | 576,4 → 547,2 (−5,1%) | 92,9 → 87,4 (−5,9%) |
| CPU главного потока | 557,7 → 526,5 (−5,6%) | 85,9 → 82,0 (−4,6%) |
| CPU worker | 18,75 → 20,70 | 6,25 → 5,47 |
| Время от начала до конца расчёта | 613,5 → 582,4 (−5,1%) | 133,9 → 122,9 (−8,2%) |
| Постоянные полные DM-кэши | 50 → 0 | 50 → 0 |
| Проверки затронутых смесей за 40 расчётов | 96360 → 0 | 19914 → 0 |

Диапазоны CPU процесса за повторы не пересеклись: пожар 575,2–581,4 против
542,8–565,7 мс; трубы 91,9–94,0 против 86,3–87,5 мс. Разницу worker не следует
приписывать изменению алгоритма расчёта: он одинаков, показания короткие и
квантуются системным счётчиком CPU. Дополнительные acquire/read/release вызовы
Rust есть, но на этом стенде экономия проверки полных смесей их перекрыла.

Память процесса (private bytes, MiB):

| Наблюдение | Пожар: legacy → API | Трубы: legacy → API |
| --- | --- | --- |
| Медиана средних по трём повторам | 1869,3 → 1842,5 | 1803,0 → 1789,0 |
| Наибольший пик обычных повторов | 1896,1 → 1924,6 | 1924,4 → 1934,6 |

**Выигрыш или ухудшение памяти не установлен.** Оба режима запускались
последовательно в одном процессе с остановленным GC; потребление растёт
с порядком случаев. Эти средние и пики нельзя выдавать за эффект API.
Для вывода нужны отдельные процессы с одинаковым стартом. Отсутствие удержанных
ссылок и освобождение сохранённой смеси проверены отдельно, но длительную
утечку на игровом раунде это не исключает.

Профайлер показывает исчезновение обходов/копий этих 50 кэшей: исключительное
время стадии копий на пожаре 37,77 → 0,28 мс, на трубах 5,33 → 0,08 мс.
Это диагностические окна с накладными расходами профайлера; их нельзя
вычитать из основных измерений. На пожаре публикация и игровые эффекты
по-прежнему занимают основную часть времени.

Перевод одного потребителя дал измеримый локальный результат; выигрыш всего
сервера и освобождённую долю ядра по нему предсказывать нельзя. Следующий
крупный потребитель — `Life/handle_environment`: он пока способен снова
запросить полную смесь на тех же тайлах в настоящей игре.

[Компактные числа и происхождение сборки](LIVE_REFERENCE_RESULTS.json).

```powershell
python tools/profiling/air_access_bench.py prepare --name unique-live-bench --dll tmp/atmos-live-ref-02/target/i686-pc-windows-msvc/release/bandastation_atmos.dll --breathers 50
python tools/profiling/air_access_bench.py compile --name unique-live-bench
python tools/profiling/air_access_bench.py capture --name unique-live-bench
python tools/profiling/air_access_bench.py report --name unique-live-bench
```
