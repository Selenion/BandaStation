# Оптимизация прототипа 2026-11-03

Текущая организация хранения и её замеры: [MEMORY_OPTIMIZATION.md](MEMORY_OPTIMIZATION.md).
Указанные ниже независимые BTreeMap относятся к предыдущему этапу.

Ниже история уплотнения и ABI 9. Итог следующего этапа ABI 11 —
[EXCHANGE_OPTIMIZATION.md](EXCHANGE_OPTIMIZATION.md): покой 13.54% CPU,
поджог 30.97%, память остаётся значительно выше DM. СМ учитывается отдельно
как диагностика с исходными runtime; экономия инфраструктуры ещё не доказана.

Профили — локальная MetaStation, Windows i686, BYOND 516.1688, rust-g 6.2.0,
без подключённых игроков. Изменения пока в рабочей ветке, default solver — DM.

Разбор оставшихся затрат и сравнение границы DM/Rust с Paradise:
[COST_AUDIT.md](COST_AUDIT.md). Экономия относительно исходного DM пока
не достигнута; быстрый Rust-расчёт перекрывается публикацией и доступом объектов.
Следующий этап сокращения обмена: [EXCHANGE_OPTIMIZATION.md](EXCHANGE_OPTIMIZATION.md).

## Представление данных

Пустые результаты реакций не требуют массива из 26 Option; нулевые моли
смеси и архива не требуют массива из 20 f32. Первая запись выделяет собственный
массив, копии независимы. Порядок газов, Some(0) против None, отрицательный
ноль и согласованные округления BYOND сохраняются.

| Встроенные поля, i686 | Исходный прототип | После |
| --- | ---: | ---: |
| Mixture | 312 B | 32 B |
| Cell | 360 B | 80 B |
| Tile | 232 B | 160 B |
| Два состояния, z 255×255 | 73.42 MiB | 29.77 MiB |

Это не полная RAM: непустые массивы, векторы версий привязок, BTreeMap,
координатные индексы, команды и объекты DM считаются отдельно. Два независимых
буфера остаются; COW для ячеек и отдельный процесс не вводились.

### Заполнение узлов таблиц

Микротест `examples/storage.rs` считает запрошенные у System байты только
в отдельном процессе. Две BTreeMap содержат 780300 записей с payload размера
текущих i686 Cell/Tile: 80/160 B; вложенных газовых массивов и DM здесь нет.
После последовательных insert узлы занимают 358635104 B на состояние;
пересборка тех же отсортированных записей через collect — 195227104 B.
Временный пик пересборки — 430907824 B. Артефакт: `tmp/atmos-storage-02.jsonl`.

Причина — частично заполненные узлы после возрастающих insert.
FromIterator стандартной библиотеки строит таблицу пакетно из отсортированных
записей ([Rust 1.86](https://github.com/rust-lang/rust/blob/1.86.0/library/alloc/src/collections/btree/map.rs)).
Store выполняет пересборку cells/tiles при сбросе начальных изменений до
первого расчёта, только если опубликованный снимок никем не удерживается.
Значения перемещаются целиком; ID, порядок, газовые числа и команды сохраняются.
Обычные тики не пересобирают таблицы. Реальная память сервера учитывается
отдельными прогонами; это измерение узлов не равно RSS/private процесса.

## Найденная регрессия CPU

Первые парные диагностические прогоны `compare-dm-idle-01` и
`compare-rust-idle-01` показали, что одного уплотнения недостаточно:

| Метрика | Исходный DM | Rust до устранения обходов |
| --- | ---: | ---: |
| CPU, % одного ядра | 13.34 | 57.88 |
| Private, MiB в окне | 1668.45–1668.61 | 2823.31–2948.78 |
| 60 игровых секунд, реальное окно | 60.11 s | 113.23 s |
| Завершённые проходы SSair | 120 | 62 |
| SSair cost в конце, сглаженная оценка | 12.72 ms | 849.46 ms |

К концу появились фоновые очаги (DM 1, Rust 2), поэтому это диагностика
постоянных затрат, не подтверждение сценария строго без реакций. Фиксированный
seed не гарантирует одинаковое дальнейшее планирование и RNG. Показатели
разных метрик не складываются; cost — не сумма CPU за окно.

`examples/idle.rs` отделяет расходы буферов от игры: 780300 пустых ячеек,
ноль активных ячеек, групп, реакций и теплопроводности. До исправления каждый
тик тратил 0.5–0.7 s на clone/обход и 0.3–0.4 s на публикацию с уничтожением
старых таблиц. Полные обходы происходили независимо от числа активных тайлов.

## Изменения расчётного пути

- Неиспользуемый предыдущий буфер возвращается следующему заданию. В него
  переносятся изменённые записи и состояние очередей; отдельные полные таблицы
  сохраняются. Удерживаемый readonly-снимок никогда не перезаписывается:
  если Arc ещё занят читателем, используется полное копирование.
- Список кандидатов покрывает активные тайлы и соседей, огонь, членов групп,
  давление предыдущего прохода и теплопроводность. Реальные изменения
  определяются прежним сравнением, без расширения численных допусков.
- Внешние записи ведут журнал затронутых ID, включая соседей при удалении,
  членов расформированной группы, замену пола и новые координаты.
- Версии привязок входят в численный снимок; новая BTreeMap всех версий
  на каждый тик больше не строится. Отсоединённые привязки учитываются явно.
- Реестры очищаются по удалённым ID. Проверка связности затрагивает изменённые
  тайлы и оба конца старых/новых рёбер; уникальность координат проверяет register.
- Общий last_share космоса нормализуется при изменении значения или внешней
  замене смеси. Повторная запись того же значения по всей карте пропускается.
- DM-упаковка сохраняет полный прежний протокол, копируя нулевые флаги
  результатов и заполняя только присутствующие значения.
- Изменение внутреннего контекста больше не выдаётся за изменение воздуха.
  Прежний wake по составу/температуре сохраняется. Записи объёма и класса
  смеси по-прежнему требуют публикации, чтобы исправить пользовательский кэш.
- Ленивый DM-кэш живёт до фактического изменения, а не один тик. Космос
  перечитывается каждый цикл, поскольку его last_share общий для всех тайлов.
- Синхронный invoke вызывает имеющийся callback напрямую, без дополнительного
  one-shot датума и списка для результата. Публикация/ошибки используют общий
  finish_callback с очередью эффектов; граница отдельного прибора сохраняется.
  Функциональная проверка — integration-42; полный замер — compare-rust-idle-04.
- Вентиляционный насос читает давление через get_readonly_air. Передача газа
  остаётся в assume_air/remove_air и по-прежнему получает изменяемую смесь.
  Покой и пустая труба больше не требуют полной обратной отправки смеси в Rust.
  integration-43 проверяет равенство DM/Rust в четырёх режимах и отсутствие
  mutable-запроса в двух случаях без переноса газа.

В `tmp/atmos-idle-final.jsonl` после двух начальных тиков последующие пустые
тики занимают менее 0.01 ms. Первое полное копирование и прогрев сюда не входят.
Четыре тика одного микротеста не доказывают ускорение игрового сервера.

## Проверка поведения

66 тестов Rust, fmt и Clippy прошли. Новые тесты сверяют всё состояние и
очередь команд переиспользованного буфера со свежей полной копией, а список
изменений — с полным сканированием. Проверены огонь, давление, группы,
стены/воздух, космос, удаление/регистрация, замена пола и удерживаемые снимки.
Отдельный случай сохраняет общее last_share космоса после полной замены смеси.

- `integration-36`: прежние 12 мировых сценариев, 49 графов × 20 тиков,
  очереди, привязки, инициализация, 21 API, контакт огня и 21 проверка панели
  прошли на новом ядре.
- `integration-37`: тот же набор, 22 API с 27 вариантами полного wire-пакета;
  всё прошло без runtime-ошибок.
- `integration-39`: 23 API, включая обновление кэша пассивного космоса после
  изменения общего last_share на другом тайле; остальные наборы также прошли.
  Golden-сценарии выполняются синхронно, как основной адаптер; 11 отдельных
  проверок механизма продолжают проверять асинхронные записи и жизненный цикл.
  Предыдущий `integration-38` не принят: один golden-сценарий охлаждения
  получил дополнительное изменение во время ожидания; источник не установлен,
  допуски и сохранённые эталоны не менялись.
- `integration-41`: 16 проверок привязок, включая снятие последнего слоя
  пола и точное сравнение DM/Rust при обмене run_later без группы на обоих
  порогах таймеров; полный прежний набор также прошёл без runtime.
- `integration-42`: тот же набор и 26 API-проверок. Прямая синхронная граница
  сохраняет рабочую смесь при вложенных вызовах/перехваченном исключении,
  очищает внешнюю фазу при ошибке и отличает числовой 0 от null. Всё прошло.
- `integration-43`: 32 API-проверки, в том числе настоящий vent_pump в покое,
  при закачке/откачке и с пустой трубой; газ/архив/температура и уведомление
  труб совпали с DM, прежний набор прошёл без runtime.
- `integration-44`: тот же игровой набор прошёл на DLL с уплотнёнными
  стартовыми таблицами. Новый Rust-тест проверяет неизменность полного
  состояния/удерживаемого снимка и последующие тики против полной копии.
- 38/38 графов, 46/46 space/planetary; исходные состояния не перезаписывались.
  Оракул использует нетронутую копию исходного HEAD. Разница полных хешей
  файлов с адаптерными hooks записывается отдельно; прежние состояния точны.
  Planetary проверяется штатным полным мировым эталоном, не заглушкой огня.
- `world-11`: полная MetaStation, 780300 ячеек, 16/16 без runtime-ошибок.
  Sampled peak private 3263799296 B; это загрузка и функциональные проверки.
  `world-10` не принят целиком: все 16 проверок прошли, но до SSair произошла
  известная ошибка исходного генератора тел с удалённым рыбьим хвостом.

## Парные игровые замеры после оптимизации

Нетронутый DM — `tmp/profiling-sources/original-head-01`, HEAD
`a72025a0480566585ab7cc48a62873581fe3a6a5`. Одинаковые карта, seed, harness,
BYOND, локальные библиотеки, прогрев и окно 60 игровых секунд. По одному
принятому захвату на вариант; это предварительные результаты без клиентов.

| Поджог 64 тайлов | 27.47 / 31.28 | 1697.0 / 2598.6 | 119 / 101 | 62.01 / 69.93 s |

Захваты: `compare-dm-idle-01` / `compare-rust-idle-06`,
`compare-dm-fire-02` / `compare-rust-fire-03` в `tmp/profiling/`.
Машинная сводка — `tmp/profiling/COMPARISON-packed-01.json`; прежние
`COMPARISON-before-sm`, `COMPARISON-invoke-idle-01`, `COMPARISON-vent-01`
сохранены для сравнения этапов. Построены `tools/profiling/compare.py`,
рядом Markdown-таблицы. На исходной пустой
станции профиль не содержит вызовов gas_reaction/*/react, хотя к концу есть
один фоновый hotspot. Число очагов само по себе не доказывает наличие химии.

В собственном прототипе idle CPU снизился с 57.88 до 18.11%, а число
проходов вернулось с 62 к 120. Однако обе новые пары хуже исходного DM;
заявлять ускорение или экономию RAM относительно DM пока нельзя.
После устранения синхронной обёртки idle machinery снизился с 48.10 до
31.11 ms, SSair — с 65.59 до 49.05 ms; CPU — с 24.53 до 23.06%.
run_callback вызывается 120 раз вместо 110543, invoke_callback не создаётся;
число самих синхронных invoke почти одинаково: 110423 / 110408.
Фоновые активные тайлы при этом отличаются: 32 / 23, повторных прогонов нет.
Это подтверждает удаление расходов обёртки, но не строгую оценку выигрыша
всего сервера. Обработка машин и пересылка газа остаются заметными затратами.
Оставшийся избыток RAM пока не объяснён полностью.

Readonly-чтение насоса: commit_air 57096 → 15454 вызовов/мин,
полный пакет 57101 → 15468, machinery 31.11 → 19.66 ms;
idle CPU 23.06 → 21.36%, private max 2939.4 → 2803.7 MiB.
После уплотнения таблиц (`idle-06`) private max — 2475.9 MiB,
ещё на 327.8 MiB меньше. Machinery почти не изменился — 19.51 ms.
На поджоге private max 2957.3 → 2598.6 MiB, CPU 31.48 → 31.28%.
Это по одному прогону на этап, фоновые события различаются; счётчики
и объём узлов подтверждают устранение конкретных расходов, но весь CPU
нельзя приписать только одной правке.

Текущая ветка с выключенной DLL: `compare-disabled-idle-01`, чистый захват,
120 проходов, 60.03 реальных секунд, CPU 11.45%, private max 1682.7 MiB,
SSair 11.51 ms. Заметной регрессии от выключенных перехватов в этом
единичном сравнении с исходным DM не видно; ускорение не доказано.

`integration-44` и пример storage завершились до прогрева `idle-06`;
во время его измеряемого окна тяжёлые проверки не выполнялись.

Взрыв СМ пока не даёт принятой пары: `compare-dm-sm-01` падает на обращении
к отсутствующей excited group; `compare-rust-sm-01` — на незавершённой
привязке после разрушения пола. Это отдельные ошибки, а не результат
производительности. Оба исправления согласованы и прошли `integration-41`;
повтор исходного DM `compare-dm-sm-guard-01` больше не падает на группе,
но не принят из-за старых ошибок z-позиции, питания голодека и гранаты.

[COMPATIBILITY_FINDINGS.md](COMPATIBILITY_FINDINGS.md).
