Сигнализации и анализаторы читают воздух тайлов и штатных портов через численный Rust API. Такое чтение больше не выдаёт живую DM-смесь, не создаёт постоянный кэш тайла и не отключает прямой путь порта. Временные списки показаний в DM остаются; это не отказ от всех DM-объектов проекта.

Переведены ручной анализатор и atmos_scan, AtmoZphere, атмосферный компьютер с датчиком, проверки тревоги, UI и circuit воздушной сигнализации. Для собственных DM-смесей ещё не перенесённых контейнеров сохраняется чтение через прежнего владельца, включая побочные эффекты его провайдера. Неизвестный слушатель теплового события по-прежнему получает живую смесь; сигнализация читает именно переданный объект с уже сделанными предыдущим слушателем изменениями.

Согласованное различие событий реализовано явно: обычный temperature_expose(null, temperature) сохраняет прежний пропуск проверки газа. Только помеченное native_reading событие читает численные показания Rust. Порядок слушателей не менялся. Это проверено отдельно от теплового события с полноценной смесью. Уже согласованное правило пустого космоса 2,7 K не менялось.

Замеры сравнивают этот этап со старыми читателями из e4b067b8c39 внутри Rust-атмоса. В обеих ветвях одинаковые worker, газовая математика, дыхание и текущий Life. Чистый upstream DM в этой серии не запускался: проценты ниже нельзя выдавать за выигрыш всего Rust-проекта над DM.

Стенд: 4096 тайлов, 50 тестовых людей, 64 настоящие сигнализации. За каждый расчёт выполняются 64 явные проверки сигнализаций, 64 чтения их UI и 64 анализа воздуха тайлов, дополнительно приходят штатные тепловые события. В сценарии труб работают 64 вентиляции, анализируются 16 портов. Это намеренно частый опрос, а не имитация обычной частоты открытия UI игроками. На каждый вариант и сценарий — три свежих процесса по 40 расчётов; порядок чередуется. Ещё четыре процесса используются только для профиля. Всего 16 процессов, 640 расчётов; 0 runtime. MC, GC и измерение ТД включены; остальная фоновая работа подсистем контролируется. Все варианты исполняют один бинарник и одну DLL BYOND 516.1688. Ресурсы снимаются только с PID сервера, не со всей машины.

В таблице медианы трёх обычных запусков; пики — максимум трёх. CPU включает всю работу окна (атмос, Life и чтение приборов), делённую на 40 расчётов. Worker измеряется собственным счётчиком потока, main — старейший поток серверного процесса. Остальные потоки и округление счётчиков объясняют возможную разность суммы main + worker и CPU всего. Причина экономии CPU видна отдельно от времени численных запросов. За 40 расчётов постоянных кэшей тайлов стало 64 → 0 в обоих сценариях, проверок смесей счётчиком стенда — 124928 → 0 при пожаре и 25916 → 0 на плазме, копирований — 64 → 0 и 6213 → 0. Все 16 анализируемых портов после каждого кадра остаются native_owned; со старым чтением их оставалось 0. Состояние газа и работа оборудования при этом совпали.

Чтение показаний само по себе не бесплатно: новый check_danger дороже прежнего чтения уже готового кэша. Выигрыш получается потому, что этот кэш больше не нужно поддерживать между чтениями. Профильные запуски не участвуют в основных CPU-цифрах. Большая публикация с игровыми эффектами остаётся основным ограничением пожара.

Корректность: полный Rust-набор i686 release с byond,simd,worker-profile пройден, включая новый тест численного пакета для тайла/порта, ожидающих операций, нулевых результатов и отсутствия публикации при чтении. Игровой набор readings-api-04: 245 проверок API, 13 новых сценариев / 37 проверок покрытия, прежние 12 сценариев мира и 49 графов / 980 шагов. Компилятор — 0 ошибок и предупреждений; неожиданных runtime нет. Проверены состав и порядок газов/реакций, нулевые ключи, вакуум/космос, повторные aliases и нумерация узлов, ручной/планшетный анализ, UI/схема/тревоги, расход датчика, ожидающие записи, неизвестный слушатель и обычное null-событие. Python-тесты сравнителя и стендов также прошли.

В производительной серии строго совпали хеши начального/итогового газа и портов, команды, число расчётов, трассы Life и признаки тревог. У чисел показаний сохраняется ранее согласованная численная погрешность. Записано 328 отличий последнего разряда текста измерения в четырёх API-прогонах пожара, например 7825,65 → 7825,66 kPa; они не скрыты из сырых результатов. Валидатор допускает только численную часть показаний в прежней точности 2e-5 с учётом вывода до 0,01. Имена, единицы, порядок, предупреждения и уровни тревоги проверяются строго. UI reference у тайла теперь идентифицирует координату/версию привязки; это ключ интерфейса, не ссылка на DM-смесь.

История проверки сохранена. readings-api-01 завершился без runtime, но прежний численный сравнитель не понимал текстовые подписи. readings-api-02 отклонён компилятором из-за ссылки в новом fixture. readings-api-03 выявил конфликт ID тестового вида с human; исправлена только изоляция fixture. В readings-api-04 первоначальный отчёт ошибочно сделал численные строки точными строками и отклонил два давления с прежней допустимой погрешностью; исходный отчёт сохранён, report-revalidated.json повторно проверяет те же данные исправленным сравнителем без нового запуска и без изменения игрового кода. Первый smoke производительного стенда не принят из-за разных сгенерированных имён вентиляций; затем имена зафиксированы до окна. Первый основной A/B остановился на округлении UI, после применения ранее разрешённой точности продолжен с теми же бинарником и данными. Итоговый report.json принят: ошибок сравнения нет. Эти отклонённые проверки не выданы за успешные новые игровые запуски.
