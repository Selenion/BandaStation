# План упрощения Rust-атмоса

Дата: 2026-11-08. Ветка: `rust-atmos-pipes`.

Цель: уменьшить задержки главного потока и общий расход ресурсов относительно
исходного Banda DM. Ускорение собственного адаптера само по себе не считается
достижением цели. Реализация и измерения ведутся по одному изменению за этап.

## Ограничения

- Сохранять формулы, порядок газообмена, баланс газа, проверку наличия перед
  изъятием, версии привязок и уже выполненные операции при ошибке обработчика.
- Сохранять живые DM-ссылки и совместимый путь для сигналов и нестандартных смесей.
- При новой подтверждённой несовместимости сначала показать сценарий и варианты
  пользователю. Нельзя незаметно менять наблюдаемую свежесть газа или порядок эффектов.
- Не исправлять посторонние runtime. Не менять железо, affinity и общий MC.
- Не делать push/PR/deploy. Первый локальный checkpoint явно разрешён пользователем;
  последующие коммиты требуют отдельного запроса.
- Сохранять эталоны, проверки реакций и баланса, компактное хранение, AVX2,
  исправления жизненного цикла и прямую публикацию через BYOND C API.

## 0. Зафиксировать исходную точку

- [ ] Сохранить этот план и локально закоммитить накопленные изменения атмоса,
  тесты и отчёты. Исключить временные каталоги, DLL и результаты компиляции.
- [ ] Сохранить SHA коммита и существующие артефакты до последующих изменений.

Контроль: актуальная принятая DLL и результаты находятся в
`tmp/atmos-operations-01/` и `tmp/atmos-pipeline-async-01/`;
описание — `OPERATIONS.md`, ключ `pipeline_async` в `OPERATIONS_RESULTS.json`.
Предыдущий обычный worker сохранён в `tmp/atmos-direct-publication-01/`.

## 1. Вернуться к обычному worker

- [ ] Исключить конвейер с задержкой обратной связи из рабочего пути:
  тяжёлые эффекты в нём выполняются после await, ожидаемого перекрытия нет.
- [ ] Сохранить протокол операций и исправления восстановления после ошибок.
- [ ] Удалить специфические очереди и обработчики конвейера, проверить includes,
  конфигурацию, Destroy/Recover и инструменты запуска.
- [ ] Проверить обычный sync/worker, порядок обратной связи, баланс газа,
  восстановление после ошибки и отсутствие повторного исполнения эффектов.

## 2. Вернуть управление MC между завершёнными порциями эффектов

- [ ] Проследить все команды world_commands, callbacks, рабочие смеси и границы
  фиксации газа. Сопоставить их с исходными MC_TICK_CHECK в SSair.
- [ ] Проверить межпорционное чтение/изменение газа, замену пола, удаление
  владельца, вложенные обращения и позднее исключение отдельным игровым сценарием.
- [ ] Если появится новое отличие игрового порядка, согласовать конкретный
  контракт до изменения рабочего планировщика.
- [ ] После согласования использовать штатную возобновляемую фазу SSair для
  полного реального пакета, а не только пустых/безопасных уведомлений.
  Порядок команд сохранять; выполненные операции фиксировать перед возвратом
  управления. Следующий расчёт не должен обгонять незавершённые эффекты.
- [ ] Не возвращать прежнюю ошибку учёта sleeping/pause: один законченный проход
  учитывается один раз; измерять частоту расчётов и tick_overrun отдельно.

Численная публикация и обновление выданных ссылок пока остаются целостными.
Её дробление — отдельная задача с отдельной проверкой совместимости.

## 3. Проверить эффект на всём DreamDaemon

- [ ] Сравнить исходный DM, checkpoint и упрощённый worker на пожаре и плазме
  через трубы. Затем проверить покой, разгерметизацию и СМ при необходимости.
- [ ] Чередовать варианты, минимум три принятых повтора. Сравнивать одинаковые
  входы, DLL/стенд и выполненную работу, а не только одинаковый seed.
- [ ] Показывать средний и пиковый ТД, p99/max интервала MC, CPU процесса,
  главного потока и worker, CPU/расчёт, число расчётов и реальную длительность,
  среднюю/пиковую/конечную private memory и RSS.
- [ ] Подробную трассу использовать для диагностики, отдельно проверить замеры
  без подробного профилировщика. Во время окна не запускать другие серверы/сборки.
- [ ] Разобраться с разбросом чистого DM: один DMB уже дал 60.06 и 69.14 с
  на одинаковое окно. Малые отличия одного прогона не считать доказанным эффектом.

## 4. Удалить исторические пути

- [ ] По фактическим потребителям убрать лишние форматы и capability probes
  промежуточных DLL. Предпочтителен один проверяемый контракт DM/DLL.
- [ ] Оставить необходимые fallback для живых смесей/сигналов/переопределений.
- [ ] Не приписывать очистке кода выигрыш CPU без отдельного измерения.

## Критерий завершения

Тесты не показывают новых несогласованных отличий поведения; результаты повторов
показывают уменьшение длинных блокировок относительно checkpoint, а сравнение с DM
честно отражает оставшиеся CPU/RAM/TD. Если основным ограничением останется
целостная публикация, следующий этап выбирается по свежей трассе, без наращивания
конвейера на предположении.
