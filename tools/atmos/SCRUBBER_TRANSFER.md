# Прямой обмен скруббера

Скруббер по-прежнему запускается из фазы воздействий SSair. Rust читает
уже выданную рабочую смесь тайла и живой порт через C API BYOND, вычисляет
перенос и записывает результат в те же списки. Промежуточный образец
фильтрации или продувки остаётся в DLL. По границе вызова передаются ссылки,
порядок фильтров, расход и статус операции.

DM сохраняет выбор тайлов, порядок широкой сети, предел давления 50 atm,
уведомление трубной сети и эффекты продувки. Штатная фаза продолжает публиковать
рабочую смесь тайла со своими правилами фиксации при исключениях. Кэши этой
фазы входят в стоимость сравниваемых режимов. Обработчики сигналов смеси,
специальные виды воздуха и незавершённые привязки используют прежний вызов.

Фильтр использует исходный порядок пересечения, вес каждого газа, округление
и минимум отбора. При нулевом выбранном составе очищаются следовые записи
без уведомления сети. Пустая продувка сохраняет активацию тайла и уведомление
сети. При отказе записи через C API Rust восстанавливает исходное содержимое
живых списков и отдельно сообщает, если само восстановление отклонено.

## Проверка поведения

103 Rust-теста и игровой прогон `tmp/atmos-phase/scrubber-transfer-01/report.json`
прошли. Сравнены 13 сценариев скруббера с исходной арифметикой DM. В том числе
порядок нескольких фильтров, следовые и нулевые газы, пустая продувка,
округление образца до нуля, предел давления и порядок широкой сети. Отдельно
проверены удержанные ссылки, сигнал слияния и исключение при уведомлении сети.
Прежние 11 сценариев вентиляции, 12 сценариев мира, 49 графов и 65 проверок API
также прошли. Сборка BYOND 516.1688 и release DLL i686.

## Сравнение

Изолированный стенд использует 32 реальных скруббера и 256 циклов, по три
прогона каждого режима с чередованием порядка. Смеси пополняются перед
каждой фильтрацией, чтобы зафиксировать объём выполненной работы. Сверяются
итоговые составы, уведомления сети и 8192 фактических переноса. Измеряется
время `scrub()` и всего цикла с подготовкой и публикацией.

| Что измерили | Штатный обмен, с | Прямой Rust, с | Снижение времени |
| --- | ---: | ---: | ---: |
| `scrub()` | 0,250 (0,234–0,271) | 0,215 (0,214–0,227) | 14,0% |
| Цикл с подготовкой, экспозицией и публикацией | 1,140 (1,128–1,147) | 1,092 (1,082–1,114) | 4,2% |

В таблице медиана и диапазон трёх прогонов. Все 8192 переноса в каждом
прямом прогоне прошли в Rust. Составы обеих сторон совпали с контролем в
допуске стенда. `scrub()` входит во время всего цикла.

В парных замерах MetaStation используется одна DLL и одна DM-сборка. Контроль
отключает только прямой обмен скрубберов с начала запуска. Оба режима включают
компактные показания, прямое смешивание труб, Rust-вентиляцию, AVX2 и worker.

По одной паре для каждого сценария, 30 игровых секунд прогрева и 60 игровых
секунд измерения. Таблицы показывают штатный обмен → прямой Rust. 100% CPU
соответствует одному логическому ядру. Worker входит в CPU остальных потоков.

завершённых расчётов атмоса. Ноль для worker соответствует разрешению
счётчика ОС.

| Покой | 1816,2 → 1814,9 | 1816,7 → 1815,3 | 2084,7 → 2078,3 |
| Пожар | 1846,0 → 2152,6 | 1855,3 → 2164,5 | 2121,4 → 2168,0 |

В контролируемой фильтрации выигрыш есть. На полной карте рабочая нагрузка
скрубберов различалась, а их время составило до 0,029 с за окно. Разница CPU
в покое и при СМ значительно больше времени скрубберов. В паре пожара разница
private около 306 MiB существовала перед окном, когда Rust успел выполнить
два прямых переноса. Внутри окна private выросла на 9,3 → 11,9 MiB. Пары
не подтверждают экономию CPU и памяти всего процесса.

Все шесть профилей приняты без новых runtime. Оба взрыва завершились
удалением кристалла. Классификатор принял известную исходную ошибку
`corpse_organ_throw_after_delete` в контроле пожара. В прогонах СМ приняты
четыре и две известные ошибки соответственно. Подробности содержатся в сырых
данных. [Счётчики, профили, входы и хеши сборки](SCRUBBER_TRANSFER_RESULTS.json)

Сводку можно пересчитать командой
`python tools/atmos/air_bridge_compare.py --scrubber-transfer --prefix scrubber-transfer-v1 --repeats 1`.

Пиковый commit превышал 2 GiB во всех запусках. Онлайн 50+ и длинный раунд
остаются за пределами стенда.
