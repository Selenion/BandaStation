# Прямое смешивание без DM-упаковки

Ветка `rust-atmos-pipes`. Этот этап удаляет повторную DM-упаковку смесей
из [переходного подключения труб](PIPE_STAGE2.md). Само владение всеми
операциями устройств в Rust ещё не перенесено: устройства и реакции работают
с обычными DM-смесями, текущий газ читается перед каждым смешиванием.

## Что изменено

Раньше для каждой смеси DM создавал полный численный пакет: текущий состав,
26 результатов реакций, архив, температуру, объём и last_share. После расчёта
DM разбирал общий ответ и заново заполнял каждый список молей.

Теперь DM собирает исходную последовательность ID и ссылок, затем делает
один вызов операции 48 на группу. Rust через официальный BYOND 516 C API
читает только `moles`, `temperature`, `volume`, выполняет прежнее численное
смешивание и пишет результат прямо в существующие списки. Неизменившиеся
значения и порядок ключей повторно не записываются. Полный пакет остаётся
только при первой регистрации смеси и для старых DLL без операции 49.

C API копирует текущие ключи/числа в Rust. Убраны промежуточные
численные списки и циклы DM, импорты каждого порта отдельным DLL-вызовом,
пересылка неиспользуемого архива и результатов, обратная DM-распаковка.
DM-смеси пока необходимы из-за прямых записей устройств в их поля/списки.
Без перехвата этих записей считать старую Rust-копию актуальной нельзя.

Операция синхронная, без yield и доступа BYOND из worker. Все полученные
C API ссылки освобождаются на выходе, включая выход с ошибкой. Пул хранит
числа, не ссылки на датумы. Архивы, reaction_results и last_share остаются
неизменными в DM; сохранённые в пуле при регистрации копии этих полей
не используются смешиванием и не считаются свежим состоянием реакций.

Весь вход проверяется до записи: размер, поколение ID, дубли привязок,
наличие списков, каталог и конечные численные значения. При ошибке входа
газ не меняется; после неё можно выполнить исправный вызов. Ошибка уже
начавшейся записи передаётся наверх без повтора операции; следующий вызов
снова читает реальные DM-данные. Нестандартные типы смесей остаются на исходном
DM-пути, чтобы сохранять переопределения `copy_from_ratio()`.

## Проверки

- 99 Rust-тестов i686 release с `byond,simd,worker-profile` прошли.
- 72 замороженных численных эталона, включая цепочку 10000 шагов, и 12
  исходных хешей прошли `pipenet.py --check`.
- Игровой стенд: 71 сравнительный сценарий и 20 проверок, новых runtime нет.
- Проверены сохранение ссылок на газ/архив/результаты, прямое изменение
  удержанного списка, замена списка устройством, изменение объёма/температуры,
  повторная ссылка на резервуар, неверный последний ID и неизвестный газ
  последней смеси, восстановление после отказа, освобождение ссылок и слотов.
- Нулевой суммарный объём сохраняет даже явно null-ключ, как ранний выход
  исходного DM; при положительном объёме такой нулевой газ очищается штатно.
- Настоящие клапан, переносной баллон с нулевым портом и SSair проверены
  прежним интеграционным сценарием. Полная игра: 0 ошибок, 0 предупреждений.

Артефакты: `tmp/atmos-pipes-world/direct-03/report.json`,
`tmp/atmos-pipenet/stage3-final-tests.log`. Состояния сравниваются в прежнем
численном допуске, а списки, порядок и служебные поля — точно.

## Изолированное сравнение

В одном загруженном игровом мире: 32 смеси, 20 газов, 500 последовательных
смешиваний с добавлением азота перед каждым шагом. Три повтора каждого пути,
порядок чередуется. Все итоговые состояния совпали в допуске исходного DM.
Измеряется включающее вложенные вызовы время `pipeline.reconcile_air()`
встроенным профилировщиком BYOND. Его нельзя складывать со временем вложенных
процедур. `world.realtime` не обновляется внутри непрерывного proc; стенд
берёт `reconcile_seconds` непосредственно из профиля завершённых вызовов.

| Путь | Три времени, s | Медиана, s | Повторных полных пакетов |
| --- | --- | ---: | ---: |
| Исходный DM | 0.210 / 0.216 / 0.208 | 0.210 | 0 |
| Прежний Rust с DM-пакетами | 0.713 / 0.720 / 0.718 | 0.718 | 16000 |
| Прямой C API | 0.069 / 0.067 / 0.068 | 0.068 | 0 |

На этом насыщенном газами участке новый путь быстрее пакетного примерно
в 10.6 раза, исходного DM — в 3.1 раза. Это не ускорение всего сервера:
обычные сети содержат меньше газов, а доля труб в общем CPU невелика.

## Замер всего процесса

Выполнены 18 запусков через `pipes_direct_compare.py --capture`: одна DLL и одна DM-сборка,
AVX2/worker в обоих режимах, MetaStation, 0 клиентов, seed 29051994,
30 игровых секунд прогрева и 60 секунд измерения. Пакетный контроль выключает
прямой путь только перед измерением; прогрев обеих сторон одинаковый.
Это диагностический параметр стенда, новый deployment-параметр не добавлен.

По три чередующиеся пары покоя, пожара и взрыва СМ. Ниже пакетный путь / прямой
путь, медианы трёх запусков; 100% CPU означает одно логическое ядро. Контроль
использует прежний пакетный Rust-путь, а не исходный DM всего сервера.

| Сценарий | Обработка труб, s | CPU процесса, % | Главный поток, % | Прочие потоки, % | Worker, % | Завершено расчётов |

Медианы разных метрик вычислены независимо и не обязаны складываться.
Worker уже входит в «прочие потоки». Его отдельный счётчик измеряет завершённые
численные задачи до Byond_Return и имеет другие границы окна и грубую точность
Windows. Поэтому его нельзя прибавлять к общему CPU или вычитать из медианы
«прочих» для точного расчёта остальных потоков.

это не время одной функции атмоса и не задержка распространения газа.
Реальные диапазоны количества расчётов: покой 120 в обоих режимах, пожар
119–120 в обоих, СМ 105–109 в обоих. Плановая частота тиков не менялась.

Обработка труб устойчиво ускорилась в 2.1 / 3.0 / 2.3 раза. Разброс времени
труб: покой 0.519–0.541 / 0.242–0.253 s, пожар 1.165–1.183 / 0.384–0.400 s,
СМ 0.824–0.854 / 0.326–0.375 s. Вложенные времена процедур не складываются.

Для общего CPU диапазоны пересекаются: покой 14.74–18.22 / 11.31–18.20%,
пожар 30.96–33.07 / 30.88–32.03%, СМ 46.27–49.82 / 41.35–48.98%.
В одних парах общий CPU ниже, в других выше. Устойчивое уменьшение общего
потребления этим экспериментом не установлено; это не основание обещать
сокращение числа машин или рост FPS с 50 игроками.

Фоновые стартовые состояния различаются даже при фиксированном seed. Например,
в первой/третьей паре СМ контроль начал с 296 сетями, прямой путь — с 332/331.
Память отличалась ещё до переключения режима: за 10 секунд до измерения во
второй паре СМ private была 1813 / 2127 MiB, в третьей — 1809 / 1851 MiB,
когда обе стороны ещё выполняли одинаковый прямой прогрев. Поэтому меньшие
пики покоя/пожара и большая память после СМ не приписываются способу обмена.
Устойчивая экономия памяти не показана. Пики всё ещё превышают 2 GiB.

Медиана повторных полных пакетов: покой 16480 / 0, пожар 48036 / 0,
СМ 30821 / 109. Последние 104–113 пакетов прямого пути — первая регистрация
смесей после разрушения/перестроения, не импорт каждого последующего шага.
Медиана групп: 1510 / 1476, 2376 / 2392, 1581 / 2016 соответственно;
ни один прямой запуск не возвращался к DM-смешиванию. В первой паре СМ
прямой путь закончил с 1752 живыми записями в 1879 слотах, во второй —
1586 в 1699, в третьей — 1767 в 1812. Свободные записи переиспользуются.

Все шесть СМ завершились настоящим взрывом и удалением кристалла. Во всех
18 запусках новых runtime нет. Покой и пожар чистые; СМ содержит по 2–4
известные исходные ошибки `sm_demoralize_missing_location`,
`holodeck_power_channels`, `tail_pin_preimpact_missing_target`,
`tail_pin_impact_missing_target`. Их состав указан отдельно для каждого запуска;
исходные ошибки по решению пользователя не исправлялись.

[Полные данные, диапазоны, счётчики и хеши](PIPE_STAGE3_RESULTS.json).
Агрегат воспроизводится `python tools/atmos/pipes_direct_compare.py --prefix directpipes-v1`.

Пожар использует прежний ограниченный сценарий: 64 тайла при 700 K,

1200 K), затем вызывается реальная взрывная деламинация с одинаковыми входами.

## Сопоставление с Paradise

Локальный Paradise `5aca8afbcf00ef1f2bb96e179bf1389289551689`:
`code/modules/atmospherics/machinery/datum_pipeline.dm` оставляет смешивание
труб в DM; `gasmixtures/gas_mixture.dm` использует dirty/API для привязанных
к тайлам смесей. Готовой реализации Rust-труб там нет. Здесь сокращается
собственная лишняя граница, а не переносится отсутствующий механизм Paradise.

Перенос всех мутирующих операций портов, реакций труб и расчётов труб в worker,
онлайн 50+ и длительный раунд в этот этап не входят. Ускорение всей игры
и уменьшение необходимой инфраструктуры не следуют из микрозамера.
