# Первый этап перехода на Rust API

Ветка `rust-atmos-api`, локальные изменения без коммита и пуша.
[План и оставшиеся этапы](AIR_ACCESS_PLAN.md), [численные результаты](AIR_ACCESS_RESULTS.json).

Новый API возвращает температуру, давление, теплоёмкость, количество и состав
газа без постоянного `/datum/gas_mixture`. На него переведены общие getters,
`TakeTemperature`, предварительная проверка зажигания и первые читатели
давления/кислорода в оборудовании, движении, речи и эффектах температуры.
Изменение температуры использует существующий Rust-протокол операций.
Старые живые DM-ссылки и их проверки сохранены до миграции владельцев.

## Проверка одинаковой работы

`tmp/atmos-api-bench-02/`: один зафиксированный игровой бинарник и DLL,
различается только `phase.value_queries_ready`. Каждый вариант на каждом
кадре выполняет одинаковые 1024 чтения температуры и теплоёмкости.
В контрольном варианте они создают и используют прежние DM-смеси.
Читатели не отключены, частота симуляции не снижена.

4096 тайлов, 40 кадров на случай, по три основных повтора каждого режима
и сценария, плюс отдельный диагностический повтор с профайлером.
Всего 16 случаев / 640 расчётов. Исходные/конечные состояния, последовательности
состояний групп, команды, показания читателей и состояния портов совпали.
Пожар: 338144 команды за случай; плазма: 19200 команд, 64 вентиляции,
2560 прямых переносов. Ошибок runtime нет.

MC и GC остановлены; квота доставки фиксирована на 128 групп команд.
Считаются CPU и память только PID сервера `19972`; максимальный промежуток
между образцами — 77 мс. Это контролируемая нагрузка общих читателей, без
игроков и фоновых подсистем. Это не замер ТД рабочего сервера.

## CPU и время

Медианы трёх основных повторов, миллисекунды на расчёт. Процедурный профайлер
в этих окнах отключён. CPU worker измеряется в его Rust-расчёте; CPU всего
процесса также включает остальные потоки. Точность потоковых часов ограничена.

| Сценарий | CPU процесса: раньше → API | CPU главного потока | CPU worker | Время кадра с ожиданием |
| --- | ---: | ---: | ---: | ---: |
| Пожар | 1212,8 → 534,2 (−56,0%) | 1190,9 → 513,5 (−56,9%) | 19,5 → 21,1 | 1246,8 → 568,9 (−54,4%) |
| Плазма через трубы | 160,9 → 78,6 (−51,2%) | 156,2 → 73,6 (−52,9%) | 5,9 → 5,9 | 193,9 → 108,2 (−44,2%) |

CPU процесса по повторам: пожар раньше 1210,2–1230,3, API 533,3–537,5;
плазма раньше 154,8–165,9, API 78,4–79,5 мс/расчёт.

Выигрыш дала ликвидация причины сверок. На пожаре число посещений накопленного
набора смесей сократилось с 1998848 до 0, на плазме — с 377423 до 0.
Постоянные полные кэши в обоих сценариях: 1024 → 0.
Вариант API выполнил 83968 прямых запросов на случай, включая подготовку.

В отдельном диагностическом прогоне затраты категории проверок/копий на пожаре
снизились с 710,4 до 0,3 мс/кадр, на плазме — с 81,3 до 0,08.
Публикация осталась дорогой: 423,4 мс/кадр на пожаре и 26,0 на плазме.
Эти числа включают расходы диагностики: их нельзя складывать с основным CPU
или выдавать за точное разложение его времени. Основной CPU включает и сами
новые запросы, даже когда они не входят в выделенную категорию диагностики.

## Совместимость и незавершённая часть

Полный набор Rust-тестов прошёл, включая два новых теста запросов.
`tmp/atmos-phase/api-values-03/`: 12 сценариев мира, 49 графов/980 шагов,
99 проверок API, 31 проверка worker, прежние проверки эффектов, ошибок,
сохранённых ссылок и замены пола — 0 расхождений, 0 runtime.
Из 99 проверок API 16 новые: состав/порядок/нули, незавершённые операции,
температура без нового ограничения снизу, приоритет живой ссылки, старый
путь и чтение последнего готового кадра во время worker без ожидания/кэша.

Расширенная инвентаризация `operation_audit.py` нашла 1675 строк-кандидатов
в 271 игровом файле / 684 procs; отдельно — реализацию смесей, адаптер и тесты.
Методы с похожими именами могут относиться к другим типам; динамические
потребители требуют ручного аудита. Список сохранён в
`tmp/atmos-api-start-01/consumer-inventory-expanded.json`.

Все потребители ещё не переведены. Следующий крупный путь: получение воздуха
в `carbon/breathe`, затем `Life/handle_environment` и температура тела. Чтения
нужно сохранять на исходных местах относительно сигналов и действий предметов;
заранее снятые числа не всегда заменяют живую смесь. Затем — обработчики
воздействия, анализаторы, переносные ёмкости и сохраняемые образцы.

Сравнение с чистым DM и выигрыш всего сервера с 50+ игроками не измерены.
Сокращение CPU в этой таблице относится к проверенным читателям в Rust-адаптере.

## Расхождение дыхания и его исправление

После измеренной части добавлены кандидат чтения общего количества газа для
`carbon/breathe` и чтение температуры для `body_temperature_skin`. Эти вызовы
не входят в нагрузку приведённого стенда. `tmp/atmos-phase/api-actors-01/`
прошёл 105 проверок API и прежние мировые/сетевые/worker-проверки без ошибок;
обычный вдох и температура кожи совпали с неизменёнными DM-процедурами
из checkpoint `c65fbacb60bddd493e079d4aa03456aae52dee64`.
Эталонные процедуры сохранены в `original_air_consumers.dm.in`, чтобы тест
не зависел от наличия старых коммитов после squash/rebase или в shallow clone.

Расширенный тест `value_breath_observes_gas_added_by_equipment_cleanup`
подтвердил несовместимость раннего численного снимка. Настоящий баллон открыт
без маски: `get_breath_from_internal()` закрывает его через `cutoff_internals()`.
`after_internals_closed()` удаляет настоящий `volume_bar`; **тестовый**
обработчик `COMSIG_QDELETING` добавляет в комнату 250 молей азота. Сам штатный
индикатор газ не производит. Это проверка сохранения поведения сигнала и
живой ссылки, а не утверждение об обычной работе HUD.

Исходный DM читает `environment.total_moles()` после этого обработчика и
получает вдох 0,398 моля. Кандидат сохранил число до обработчика и получает
0,199 моля. Баланс газа сохраняется, но расход кислорода и выдох отличаются
вдвое. Это не принятая численная погрешность. Исходные данные:
`tmp/atmos-phase/api-actors-reentry-02/value-breath-reentrancy.json`.

Пользователь выбрал живой Rust-доступ. Он реализован: количество читается на
прежнем месте, старые ссылки удерживают прежнюю смесь при смене пола.
`live-reference-05` прошёл 126 проверок API и прежние мировые/сетевые/worker
проверки без расхождений и runtime; вдох теперь 0,398 / 0,398 моля.
[Механизм, владение и границы проверки](LIVE_REFERENCES.md).
В Paradise `bound_to_turf/set_dirty()` обновляет выданную копию немедленно;
одно заранее прочитанное число этот контракт не заменяет.
