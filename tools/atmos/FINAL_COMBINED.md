# Итоговая комбинация оптимизаций: DM против Rust + AVX2 + worker

Дата замеров: 2026-11-05. Все результаты получены заново на текущем рабочем дереве
`rust-atmos-experiment` от `183cdcde1e6`; включены последние исправления удаления пола и очагов F11.

18 принятых запусков: по три на режим и сценарий. Отдельно сохранён один диагностический запуск
неизменённого DM на СМ. Старые измерения не включены в эти медианы.

## Условия

- Windows, Intel i7-10700F, 8 физических / 16 логических CPU, план High performance; affinity не менялась.
- BYOND 516.1688, 32-битный DreamDaemon, MetaStation, 255×255×12 = 780300 ячеек. Подключённых игроков: 0.
- Исходный DM: `a72025a0480566585ab7cc48a62873581fe3a6a5`.
- Rust: release, `i686-pc-windows-msvc`, features `byond,simd,worker-profile`, `RUST_ATMOS_THREADED`.
  Во всех Rust-запусках подтверждены включённый worker и доступность AVX2.
- Обе DMB скомпилированы одинаковым профилирующим стендом (`-DCBT`, компилятор сообщает DEBUG mode).
  В обоих режимах включён BYOND world.Profile. В Rust дополнительно включены существующие счётчики worker; их стоимость не вычиталась.
- Старты последовательные, без конкурирующих серверов этой серии; порядок режимов чередовался.
  DMB переиспользуется только внутри одного режима, DLL одна для всей серии.
- Начальный seed 29051994, 30 игровых секунд прогрева и окно около 60 игровых секунд.
  Реальная длительность окна измеряется отдельно; одинаковый seed не гарантирует одинаковую фоновую работу.
- Покой: обычная работа станции без искусственной аварии. Пожар: 64 одинаковых тайла, O₂=100, N₂=300, plasma=20 mol, 700 K.
- СМ: 33 тайла камеры, 300 mol плазмы на тайл, 1200 K, internal_energy=5000;
  принудительный вызов настоящей explosive delamination с радиусом 35, центр (169,154,2).
  Отсчёт до взрыва исключён. Во всех принятых запусках кристалл удалён и входы сценария совпали.

## CPU всего процесса и потоков

CPU-ms / расчёт — CPU всего сервера, делённый на завершённые тики атмоса; это не чистая стоимость или длительность атмоса.
Счётчики ОС накопительные, опрос примерно раз в секунду. Средний CPU считается между первым и последним отсчётами внутри окна.
CPU-s полного окна оценены как средний CPU × реальная длительность; граничные участки не измерены точно.
Медианы разных столбцов могут относиться к разным повторам и не обязаны складываться точно.

## Ошибки и контроль СМ

Неизменённый исходный DM в `final-01-dm-sm-plasma` воспроизвёл пять ранее известных ошибок
отсутствующей excited group (reset_cooldowns / dismantle_cooldown). Обработка отдельных тайлов оборвалась.
Этот запуск отклонён для основного сравнения, сохранён как диагностика и не заменён задним числом.

Исходный DM, диагностический СМ: 41.02% CPU, Main 40.82%, остальные 0.19%; private max 1715.1 MiB, working set max 1687.8 MiB, peak commit 1997.4 MiB; 110 проходов за 65.53 s. Эти проходы не гарантируют полной обработки тайлов.

Три основных DM-контроля СМ используют свежую отдельную копию того же исходного коммита с ранее согласованной
проверкой наличия группы. Изменён только `LINDA_turf_tile.dm`: при отсутствии группы пропускается обращение к её таймерам.
Rust-адаптера в этом контроле нет. Хеши оригинала и патча сохранены в JSON. Повторы заведомо падающего оригинала №2/3 заменены этими явно обозначенными контролями.

Известные исходные runtime не считаются автоматическим провалом: их точные сигнатуры и доказательства
сохранены проверяющим скриптом. Они могут менять объём выполненной неатмосферной работы, поэтому сравнение СМ остаётся с этим ограничением.
Новые/неразрешённые ошибки в принятых запусках отсутствуют; игровые объекты ради замера не исправлялись.

`final-03-dm-atmos-fire` первоначально получил exit 1 из-за ошибки throw_at при создании трупа.
Она произошла на неизменённом DM до измерительного окна. В проверяющий скрипт добавлена точная сигнатура
с обязательным контекстом corpse organ_loss. Замер принят повторной проверкой без перезапуска.
Исходные exit, manifest и runtime-validation сохранены; основание принятия находится в отдельном reviewed-manifest.json.
Аналогично принят `final-03-dm-guard-sm-plasma`: две ошибки tail_pin в pre_impact/throw_impact
воспроизвелись без Rust в неизменённом коде метания. Для них добавлены точные правила с проверкой типа предмета;
ошибки других объектов остаются неразрешёнными. Финальные 12 тестов классификатора прошли.
Обе повторные проверки сохранили исходные отказы и сырые измерения.
Измерительный DM-стенд, DMB, DLL и игровой код не менялись.

## Проверки и воспроизведение

- Свежая итоговая DLL: 88 Rust-тестов прошли.
- Игровой фазовый стенд с этой DLL: 12 сценариев, 49 графов / 980 шагов, 31 worker-проверка; failures пуст.
- Проверены обмен с DM, восстановление после ошибки эффекта, замена пола и жизненный цикл очагов топливной лужи.
  Это локальные эталоны поведения, не доказательство идентичности любого полного игрового раунда.
- Перед записью отчёта перепроверены хеши 13330 входных файлов и diff. За время серии менялись только классификатор runtime и его тест, с отдельной записью политики; измеряемый код не менялся.
- DLL SHA256: `9443e1b12290d413428c376eb10d870dd4407be3b54d7f8acf7e9103b26359e4`.
- Полные метрики, диапазоны, хеши DMB/логов, исходные условия и статусы: [FINAL_COMBINED_RESULTS.json](FINAL_COMBINED_RESULTS.json).

из-за разного числа DM-вызовов. По коротким локальным окнам нельзя обещать такую же разницу на рабочем сервере.
