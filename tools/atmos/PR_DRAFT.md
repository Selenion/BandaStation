# WIP: экспериментальный Rust backend атмоса BandaStation

Локальный черновик описания для ревью. Публикации PR нет. Текущие результаты
не обосновывают включение Rust на рабочих серверах: CPU/RAM пока выше DM.

Причины регрессии: [COST_AUDIT.md](COST_AUDIT.md). Последующее сокращение обмена,
согласованные исправления и итоговые измерения ABI 11:
[EXCHANGE_OPTIMIZATION.md](EXCHANGE_OPTIMIZATION.md).
Следующий этап хранения: [MEMORY_OPTIMIZATION.md](MEMORY_OPTIMIZATION.md).
Он сократил живые Rust-аллокации с 460.8 MiB в предыдущем аудите до 247.9 MiB;
хранение Cell/Tile — примерно с 372.9 до 181.9 MiB. Пики памяти процесса
зависят также от фоновых объектов и удержания памяти аллокатора.

## Что этот PR делает

Добавляет явно включаемый backend SSair: Rust считает газообмен, 20 газов,
26 реакций, возбуждённые группы, hotspot и теплопроводность по правилам Banda.
Предметы, мобы, устройства и трубы остаются в DM и обращаются к воздуху через
ленивый API. Полное DM-зеркало газа карты не создаётся. Пустая настройка
`RUST_ATMOS_LIBRARY` сохраняет штатный DM backend.

Численное состояние привязано к координатам; смена пола сохраняет ячейку,
а версия привязки защищает её от старых эффектов. Наследование воздуха
сохраняет группу и таймеры. Загрузка шаблонов ждёт успешного Initialize;
временная блокировка тайла сохраняет смесь и её тип. Пакетные мировые эффекты
выполняются в DM между расчётами, как согласовано для этой реализации.

Счётчики и группы админской панели читаются из Rust с прежними правами доступа.
Несовпадение ABI/каталога и ошибки native-операций сообщаются явно.

В исходном DM исправлен один согласованный дефект: заключительный run_later
обмен может пройти без excited group. В таком случае пропускаются только
таймеры отсутствующей группы; газ, давление, реакции и экспозиция продолжаются.
Такое же поведение реализовано в Rust. Ошибки СМ/голодека/гранат, не связанные
с переносом атмоса, оставлены по решению пользователя.

Два логических Rust-состояния разделяют неизменённые блоки по 8 записей;
запись отделяет свой блок, сохраняя удержанные снимки. Затронутые блоки
синхронизируются повторным совместным использованием актуального состояния.
Пустые моли/результаты занимают память при первой записи, кэши DM обновляются
по фактическим изменениям, синхронные вызовы обходятся без дополнительного
датума очереди. Плотные блоки заменяют узлы BTreeMap; стартовая пересборка
таблиц больше не нужна. Проверка давления вентиляционного насоса использует readonly
доступ; закачка и откачка продолжают использовать изменяемую смесь.

Оборудование исполняется в общей безопасной фазе с записью изменённых смесей
до паузы MC. Согласовано сохранение выполненных записей при исключении машины.
Компактный обмен ABI 11 и ленивые эффекты сокращают повторную сериализацию.
Общий atmos_spawn_air использует API Rust, сохраняя газовый архив, цикл,
температуру пола и активацию; это проверено настоящим углём и заменой пола.

## Почему это хорошо для игры

Получается проверяемая основа для сравнения native-атмоса с текущими механиками
Banda. Реестр поведения, газовые взаимодействия и эталоны позволяют находить
регрессии до тестового подключения.

Экономия инфраструктуры пока не доказана. Полные игровые сравнения и границы
измерений приведены в [OPTIMIZATION.md](OPTIMIZATION.md); даже после снижения
затрат относительно первого прототипа текущая версия требует дальнейшей
оптимизации относительно DM. Этот PR следует оценивать как эксперимент.

| Сценарий | CPU DM / Rust, % ядра | Private DM / Rust, MiB, максимум | Проходы SSair DM / Rust |
| --- | ---: | ---: | ---: |
| Покой | 13.34 / 16.40 | 1668.6 / 2551.7 | 120 / 120 |
| Поджог | 27.47 / 28.09 | 1697.0 / 2261.6 | 119 / 107 |

По одному захвату без игроков. СМ учитывается отдельно как диагностика с
исходными DM-runtime, которые пользователь указал оставить без исправлений.
Итоговый SM-прогон после оптимизации памяти имеет два известных исходных runtime — null.z и
removeStaticPower голодека; он не включён в чистые сравнения. Полная сводка содержит
все runtime и ограничения, а не только показатели CPU/RAM.

## Изображения изменений

Новых карт, спрайтов и интерфейсов нет. Проверена серверная часть существующей
панели атмоса; открытие TGUI настоящим клиентом ещё не проверено.

## Тестирование

- Windows i686, BYOND 516.1688, локальный rust-g 6.2.0: release-сборка,
  fmt, Clippy, 72 теста Rust.
- `integration-memory-04`: 12 мировых сценариев, 49 графов по 20 тиков,
  11 проверок очередей/жизненного цикла, наследование пола, 16 привязок,
  7 отложенной инициализации, 32 API, парный контакт с огнём,
  21 проверка панели/ошибок, 20 обмена и ленивых эффектов, 6 сравнений
  helper с DM, ошибка оборудования 102/102 моля. Расхождений и runtime нет.
- До этапа ABI 11 `world-11`: полная MetaStation, 780300 ячеек, 16/16 проверок,
  включая двери, доступ к газу, замену пола и прямой hotspot.
- `world-memory-02` с прототипом блоков 128: 16/16 функциональных проверок
  полной карты; строгий фильтр отклонил прогон из-за исходного runtime рыбьего хвоста.
  Окончательные блоки 8 прошли `integration-memory-04`, три загрузки/профиля полной
  карты и отдельную перепись реально общих блоков. СМ остаётся диагностикой.
- Сохранённые сравнения химии/обмена/тепла и отдельный реестр
  [BEHAVIOR.md](BEHAVIOR.md). Эталоны не перезаписывались под Rust.
- Парные профили пустой станции и поджога, отдельно диагностика настоящего
  взрыва СМ на плазме. Исходная база материализована из HEAD; параметры,
  бинарники, входы и сырые профили сохранены. Окончательные текущие числа —
  в [MEMORY_OPTIMIZATION.md](MEMORY_OPTIMIZATION.md), структурированные
  результаты — [MEMORY_RESULTS.json](MEMORY_RESULTS.json).

Целевая BYOND 516.1685/rust-g 7, Linux-рантайм, все карты, полный раунд и
50+ игроков ещё не проверены. Штатный check_grep локально не завершён:
до отсутствующего jq он нашёл существующий lowertext в TGS из исходного HEAD.
Несвязанные участки не исправлялись. Добавлен workflow сборки/численных
проверок Rust; облачный CI пока не запускался.
