# Хранилище трубных смесей и подключение к SSair

Ветка `rust-atmos-pipes`, база `995fbfb91e9`. Реализован пул Rust с ID и
поколениями и подключено численное смешивание из штатной фазы труб SSair.
Это переходная интеграция: устройства ещё работают с существующими DM-смесями,
которые синхронизируются перед каждым смешиванием. Полное устранение этой
копии зависит от переноса операций устройств. Реакции пока выполняет исходный DM.

## Владение и порядок

`pipenet::Pool` хранит текущий газ, архив, результаты и last_share. Порты и
основная смесь сети имеют отдельные записи. Повторная ссылка на общий резервуар
получает тот же ID; после освобождения слот переиспользуется с новым поколением.
Старый handle не может читать, менять или удалять новую смесь.
Пул находится вне снимков тайлов: worker атмосферы не копирует его каждый тик.
Уничтожение владельца освобождает таблицу и газовые массивы.

Привязка хранит слабую ссылку на DM-смесь. `Destroy()` освобождает запись сразу,
а для обычной сборки мусора SSair проверяет до 256 привязок за проход.
Закрытие адаптера отсоединяет живые DM-смеси; их газ остаётся доступен.

Точка подключения — после штатного сбора смесей в `pipeline.reconcile_air()`.
Сохраняются порядок сетей/смесей, специальные соединения клапанов и баллонов,
выравнивание до реакции и реакция только основной смеси текущей сети.
Выполняется один выходной пакет на группу; импорт каждого действующего
DM-представления пока выполняется отдельно. Списки текущего газа обновляются
на месте, архивы/результаты и объёмы не перезаписываются.
Смеси с переопределённым поведением остаются на штатном DM-пути; ускоренный
путь сейчас применяется только к точному типу `/datum/gas_mixture`.

Подключение действует внутри уже включённого Rust-атмоса. Пустая настройка
библиотеки сохраняет обычный DM. Старые DLL ABI 11 без новых операций
продолжают работать с DM-трубами; новая возможность проверяется при запуске.
Новые deployment-параметры и CPU affinity не добавлены.

## Проверки

- Все 98 тестов целевой i686 release с `byond,simd,worker-profile` прошли.
- 72 численных эталона, включая 10000 шагов, остаются в допуске исходного DM.
- В реальном игровом мире прошли 71 сравнительный сценарий и 10 проверок:
  клапан в штатной фазе SSair, переносной баллон с нулевым портом, удерживаемый
  список газа, освобождение и повторное использование записей, сборка мусора,
  закрытие с живой смесью. Архивы и last_share сохранены.
- Полная игра компилируется без ошибок и предупреждений.
- Парсер труб допускает штатный нулевой объём, сохраняя прежнюю проверку
  положительного объёма для пакетов тайлов. Ошибочный ID и неверный выходной
  список отвергаются до изменения газа.

Игровой артефакт: `tmp/atmos-pipes-world/pool-03/report.json`; нативные тесты:
`tmp/atmos-pipenet/stage2-all-tests.log`. Изолированный математический эталон
проверяется `python tools/atmos/pipenet.py --check`; из исходника удаляется только
аддитивная диспетчеризация в Rust перед сверкой старого хеша, не сама математика.

Полный перенос с удалением DM-представлений и перенос реакций в worker ещё
не выполнены. Настоящие перестроения разрушенной станции дополнительно
проверяются диагностическими прогонами СМ, а не объявляются покрытыми
проверкой одной записи пула.

## Замеры

Сравниваются старая DLL до трубного пула и новая DLL на одной DM-сборке;
оба режима используют AVX2 и worker. Это контроль данного этапа, не сравнение
с исходным DM. Покой, пожар и взрыв СМ на плазме выполняются последовательно,
по одному парному прогону. Эти диагностические пары недостаточны для оценки
стабильного выигрыша; число фоновых сетей и другие состояния мира различаются.

В первой паре покоя обработка труб заняла 0.235 s против 0.662 s за 60 игровых
секунд. Новый путь дополнительно импортирует DM-пакеты, так что быстрый
численный код сам по себе не уменьшил стоимость границы.
Разность максимумов private memory около 290 MiB пришлась на временный пик:
к концу окна private составила 1857.6 / 1861.5 MiB. Пиковый commit за весь
запуск составил 2139.8 / 2147.6 MiB. Оценивать память пула этой разностью
пиков нельзя. Контрольный компилятор завершался около начала окна покоя;
результат сохранён как диагностика, не как точная оценка разницы CPU.

[Машиночитаемый агрегат](PIPE_STAGE2_RESULTS.json) воспроизводится
`python tools/atmos/pipes_compare.py`. Все шесть запусков завершены; одна DM-сборка,
предыдущая DLL `9443e1b12290…` и новая `bcd66375deb4…`, Windows, BYOND 516.1688,
i686 release с AVX2/worker, MetaStation, 0 клиентов, 60 игровых секунд.
Число фоновых сетей различается: покой 343 / 331, пожар 296 / 296,
СМ 296→378 / 296→371. Поэтому вся разность процесса не приписывается трубам.

служебные потоки; отдельный worker — счётчик завершённых численных задач
до Byond_Return, с другими границами и грубым округлением Windows.

В новых запусках возвратов к DM-смешиванию не было. После СМ живы 1578 записей

Пиковая память всего процесса по-прежнему превышает прежний ориентир 2 GiB.

Новых runtime атмоса во всех шести запусках нет. В новом пожаре принят один
подтверждённый исходный `corpse_organ_throw_after_delete`; в обоих СМ — по одному
`sm_demoralize_missing_location` и `holodeck_power_channels`. Кристалл удалён
в обоих СМ. Ошибки относятся к исходному игровому коду и не исправлялись.

Экономия ресурсов этим переходным слоем пока не подтверждена. Следующее
сокращение расходов должно убирать повторный импорт DM-смесей и переводить
операции портов на native ID. Ранний микрозамер смешивания отдельно
приведён в [первом этапе](PIPE_STAGE1.md).
